# 0.3.9.3 — 2026-09-18

## Что нового

### Проверка обновлений конфигураций 1С переведена на реальный ресурс `releases.1c.ru`
Проверка обновлений конфигураций 1С теперь работает с официальным ресурсом обновлений вместо
прежнего механизма, который опирался только на HTTP Basic Auth и не принимался порталом.

Что изменилось:
- **Авторизация через портал 1С** (`login.1c.ru`, Spring Security CAS): GET формы → токен
  `execution` → POST `/login`, сессионные cookie сохраняются. Логин/пароль задаются в окне
  **Настройки**.
- **Определение последней версии** — со страницы `https://releases.1c.ru/project/<ник>`
  (таблица `#versionsTable`, первая строка = последняя версия).
- **Скачивание дистрибутива** — через `https://releases.1c.ru/version_files?nick=<ник>&ver=<версия>`
  (JSON со списком файлов → выбор дистрибутива → загрузка).
- **Ручное следование редиректам** с повторной передачей учётных данных (Basic Auth не теряется
  при переходе на CDN).
- Ник `AccountingCorp30` подтверждён для «Бухгалтерия предприятия» (3.0). У остальных
  предопределённых конфигураций ники очищены (не подтверждены) — при отсутствии ника проверка
  честно сообщает об ошибке.
- Добавлено диагностическое логирование `[Updates]` (URL, код ответа, тип исключения).

## Исправления

- **Исправлен дефект сохранения каталогов шаблонов в настройках (Windows/WPF)** — при открытии
  окна «Настройки» список «Каталоги шаблонов» (`TemplatePathsList`) не заполнялся сохранёнными
  значениями, из-за чего нажатие «ОК» затирало их пустым списком. Список теперь заполняется из
  `MainViewModel.TemplateCatalogPaths` (добавлено свойство для WPF, как в Avalonia).

## Исполняемые файлы

- **Windows x64** — `dist/win-x64/ConfigurationManagement.exe`
- **Linux x64** — `dist/linux-x64/ConfigurationManagement`

## Сборка обеих платформ

- Windows: `dotnet build "Configuration Management/Configuration Management.csproj"`
- Linux: `dotnet build "Configuration Management/Configuration Management.csproj" -p:ForceLinux=true`

Обе сборки проходят без ошибок.

# Управление конфигурациями 1С — 0.3.8.19

## Раздельные учётные данные для запуска и хранилища

В этой версии реализован **Этап 12** дорожной карты StartManager: раздельные учётные данные
(имя пользователя/пароль) для режимов «Конфигуратор» и «1С:Предприятие», а также для
Хранилища конфигурации (функция №7). Каждый набор используется при запуске
соответствующего режима и передаётся ключами командной строки. Реализовано для
**Windows/WPF** и **Linux/Avalonia**.

### Что нового

- **Отдельные учётные данные для трёх сценариев** — для каждой информационной базы
  задаются независимые логин/пароль:
  - для запуска **«1С:Предприятие»** (`EnterpriseAuth`) — передаются ключами `/N` `/P`;
  - для запуска **«Конфигуратор»** (`ConfiguratorAuth`) — передаются ключами `/N` `/P`;
    признак «Авторизация как для 1С:Предприятия» позволяет копировать учётные данные
    Предприятия;
  - для **Хранилища конфигурации** (`Repository.User` / `Repository.Password`) —
    передаются ключами `/ConfigurationRepositoryN` / `/ConfigurationRepositoryP`
    при запуске Конфигуратора.
- **Единый резолвер учётных данных** — платформенно-нейтральный
  [`Services/InfobaseAuthResolver.cs`](../Configuration%20Management/Services/InfobaseAuthResolver.cs)
  теперь разрешает все три набора: добавлен метод `ResolveRepository`, возвращающий
  отдельные логин/пароль Хранилища. Резолвинг Хранилища используется при построении
  строки запуска ([`Services/OneCLauncher.Arguments.Shared.cs`](../Configuration%20Management/Services/OneCLauncher.Arguments.Shared.cs)).
- **Обратная совместимость** — если раздельная авторизация Предприятия/Конфигуратора не
  задана, используется авторизация информационной базы (`Connection`); учётные данные
  Хранилища остаются в собственных реквизитах и не влияют на авторизацию запуска.
- **Безопасное хранение** — наборы учётных данных сохраняются в профиле (`infobases.json`)
  и включаются в резервные копии профиля; пароли не логируются и скрыты в интерфейсе
  (показ только по явному действию пользователя).
- **Тесты** — новые регрессионные тесты
  [`ConfigurationManagement.Tests/Etap12AuthTests.cs`](../ConfigurationManagement.Tests/Etap12AuthTests.cs)
  покрывают раздельное разрешение всех трёх наборов и обратный откат к авторизации базы.

### Как использовать

1. Открыть свойства информационной базы (контекстное меню → «Свойства»).
2. На вкладке подключения/запуска задать:
   - **«1С:Предприятие»** — логин/пароль для запуска клиента;
   - **«Конфигуратор»** — логин/пароль для запуска конфигуратора (опционально включить
     «Авторизация как для 1С:Предприятия»);
   - **«Хранилище конфигурации»** — адрес сервера, имя хранилища и отдельные логин/пароль.
3. Сохранить. При запуске Предприятия/Конфигуратора и при работе с хранилищем программа
   передаст соответствующий набор учётных данных.

### Известные ограничения

- Отдельные учётные данные хранилища используются при запуске Конфигуратора с подключением
  к хранилищу; операций обмена с хранилищем (например, пакетного взятия/фиксации) в текущей
  версии приложения нет — ключи `/ConfigurationRepository*` передаются лаунчером платформе.
- Пароли хранятся в профиле так же, как и ранее (без шифрования на диске); они скрыты в
  интерфейсе и не попадают в журналы.

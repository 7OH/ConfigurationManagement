# 0.3.9.1 — 2026-09-18

## Что исправлено

### #260 — Закрытие окна «Определение конфигураций всех баз» без двойного вопроса на Windows
Фикс 0.3.9.0 ушёл только в Linux/Avalonia; WPF-обработчик `OnClosing` не имел флага `_closeConfirmed`,
из-за чего вопрос подтверждения повторялся. Добавлен флаг `_closeConfirmed` (ранний выход при
`e.Cancel`), закрытие при отказе отменяется (`e.Cancel = true`).

### #255 — Убран «необоснованный» горизонтальный скролл при запуске списка
Для дерева `MainTree` горизонтальная полоса отключена (`ScrollBarVisibility=Disabled`), при
восстановлении позиции после пересборки сбрасывается `HorizontalOffset=0`. Вертикальная пиксельная
виртуализация сохранена.

### #252 — Точное восстановление позиции списка после правки свойств базы
Позиция запоминается не по абсолютному offset, а по верхней видимой строке (индексу/ссылке);
применяется только на последнем (ApplicationIdle) проходе восстановления, чтобы второй проход не
затирал позицию; добавлен clamp к `ScrollableHeight`.

### #251 — Выбор «папки» платформы больше не подставляет разрядность x86
При выборе частичной версии («8.3» / «8.3.27», «папки») приоритет разрядности больше не ставится на
«Приоритет 32»: добавлен хелпер `HasExplicitArchitecture`, запись разрядности выполняется только при
явном суффиксе «(32)/(64)». Симметрично на Windows/WPF и Linux/Avalonia.

### #250 — Двойной клик по всей ширине колонки «Платформа»
Ячейка платформы обёрнута в растягивающийся прозрачный контейнер с `Tag="PlatformVersion"`, поэтому
двойной клик и по надписи, и по пустой области колонки открывает выбор версии, а не запускает базу;
совместимо с `ReorderGridColumns`.

## Исполняемые файлы

- **Windows x64** — `dist/win-x64/ConfigurationManagement.exe`
- **Linux x64** — `dist/linux-x64/ConfigurationManagement`

## Сборка обеих платформ

- Windows: `dotnet build "Configuration Management/Configuration Management.csproj"`
- Linux: `dotnet build "Configuration Management/Configuration Management.csproj" -p:ForceLinux=true`

Обе сборки проходят без ошибок.

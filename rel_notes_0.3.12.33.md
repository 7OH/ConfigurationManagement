# 0.3.12.33

## Исправлено

### issue #371 — «Обновление: версия не распарсена / определена неверно» (Розница/УПП)

- Короткие страницы каталогов `releases.1c.ru/project/<ник>` (без `allUpdates=true`, len≈11760)
  не содержали таблицы `#versionsTable`, ссылок `version_files` и атрибутов `data-ver` — версия
  искалась по версионным токенам текста. Посторонний токен «4.2.0» (версия другого продукта)
  ошибочно принимался за версию конфигурации: Розница предлагала 4.2.0 вместо максимальной
  3.0.14.168, УПП — вместо 1.3.285.2.
- Ужесточён фильтр версионных токенов: отсекаются токены с первым сегментом вне 1–3
  (версии конфигураций 1С) или 8 (платформа) — «4.2.0», «7.1.0», «9.х» больше не считаются
  версиями каталога; отсев дат/годов сохранён.
- При «подозрительной» версии (первый сегмент ≥ 4, например версия платформы 8.x)
  выполняется повторный запрос с `allUpdates=true#updates` — полный каталог содержит
  таблицу `#versionsTable` и даёт правильную версию конфигурации.
- Платформенный парсер каталога поддержал карточный дизайн Розницы/УПП: версии распознаются
  по ссылкам `version_files`/`version_file` (версия из текста или `ver=` query), атрибутам
  `data-ver`/`data-version` и версионным токенам. Единая логика сбора вынесена в
  `OneCUpdatesService.CollectVersionCandidatesFromHtml` и используется обоими парсерами.

## Тесты

Добавлено 7 тестов (`OneCUpdatesParsingTests`, `OneCPlatformCatalogParserTests`,
`UpdateCheckCatalogTests`): фильтр посторонних токенов, короткая страница с «4.2.0» и реальной
версией, распознавание «подозрительной» версии, карточный дизайн (ссылки + data-атрибуты,
токены без ссылок, только посторонние токены), повтор запроса с `allUpdates=true` при
подозрительной версии (fake HTTP handler).

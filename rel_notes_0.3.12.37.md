# 0.3.12.37

## Исправлено

### issue #371 — «Обновление — версия не распарсена» (замечание 7OH)

- **Неверная версия (Розница/УПП показывали «2.2.10»).** Короткая страница
  `releases.1c.ru/project/<ник>` (без `allUpdates=true`) содержит посторонний токен
  «2.2.10» — первый сегмент 2, поэтому прежний фильтр «подозрительной версии»
  (`LooksLikeForeignVersion`) его не отсекал, и повтор с полным каталогом не срабатывал.
  Теперь для URL вида `project/<ник>` полный каталог (`allUpdates=true#updates`)
  запрашивается **всегда** — он содержит таблицу `#versionsTable` и даёт корректную
  последнюю версию (Розница: 3.0.14.168 вместо 2.2.10; УПП — аналогично). Версия
  короткой страницы используется только как fallback, если полный каталог
  недоступен/не распарсился.
- **Отладочный флаг `CM_UPDATES`** (в `trace.json` или env `CM_UPDATES=1`): при включении
  в журнал пишутся детальные логи проверки — тип URL, длина ответа, найденные кандидаты
  версий с их списком, выбранная версия и решение о повторе с полным каталогом.
- **Кнопка «Список конфигураций» в окне «Проверка обновлений» (F9)** — внизу слева:
  открывает список типовых конфигураций, чтобы проверить ссылки каталогов релизов сразу.
- Обе платформы: WPF и Avalonia.

## Тесты

Добавлено 2 теста (`UpdateCheckCatalogTests`): короткая страница с посторонней «2.2.10» →
всегда запрашивается полный каталог и берётся верная версия; полный каталог недоступен
(500) → fallback на версию короткой страницы.

- Полный прогон тестов: 2586/2586 зелёных (2584 прежних + 2 новых).
- Ручной чек-лист: F9 по базе Розницы/УПП — последняя версия совпадает с каталогом

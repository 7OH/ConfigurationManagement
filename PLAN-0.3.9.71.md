### #294 Блокировка приложения (7OH: «не блокирует ничего», «поле не активировано», «не закрыть никак кроме пароля», «повторный вызов снова показывает разблокировку»)

Текущая реализация (`MainViewModel.SessionLock.cs:63`, `MainViewModel.Avalonia.SessionLock.cs:43`):
команда «Блокировка приложения» при заданном пароле сразу показывает МОДАЛЬНОЕ окно
разблокировки, из которого нельзя выйти без верного пароля (`Closing → e.Cancel`).
Итог: вызов «Блокировки» немедленно требует пароль; после ввода ничего не заблокировано;
состояния блокировки как такового НЕТ. Плюс фокус в поле пароля ставится ненадёжно
(`Loaded`/`Opened` → `Focus()` без повторного поста).

**Решение — постоянное состояние блокировки:**
1. `IsAppLocked` в `MainViewModel` (runtime, не сохраняется).
2. «Блокировка приложения»: пароль не задан → модальная установка (как сейчас, отмена = выход);
   затем `LockNow()`: `IsAppLocked = true` + оверлей поверх содержимого главного окна
   (полупрозрачный, «Приложение заблокировано», клик → окно ввода пароля) + открытие окна разблокировки
   **в немодальном** режиме с владельцем.
3. Окно разблокировки снова закрываемое (крестик/Отмена/Esc): закрытие НЕ снимает блокировку.
   Верный пароль → `Unlock()`: состояние сброшено, оверлей скрыт, окно закрыто.
4. Пока `IsAppLocked`: ввод в главное окно перехватывается (оверлей `IsHitTestVisible`; PreviewKeyDown →
   открыть диалог, `Handled`), активация окна → открыть диалог. Повторный вызов команды → просто открыть диалог.
5. Фокус в поле пароля: после показа через `Dispatcher` пост с низкой приоритетом (обе платформы).

### #296 Больше компактности (7OH: «заголовок стал меньше, строка — та же высота», Windows)

Замер в изолированном портативном профиле (UI Automation, реальное приложение 0.3.9.70):

| Элемент | Обычный | Компакт |
|---------|---------|---------|
| Строка базы (с рядком тегов) | 56 | 48 |
| Строка базы без тегов | 39 | 32 |
| Заголовок группы | 39 | 28 |

Причины (MainWindow.xaml):
1. **Кнопки звезды/булавки — 32px в обоих режимах**: на них не задан стиль, применяется неявный
   стиль кнопки MaterialDesign (`MaterialDesign3.Defaults.xaml` в App.xaml:12) — кнопка раздувается
   до высоты ~32 и держит всю главную линию строки (репро без темы даёт 14px).
2. **Кнопки действий**: компакт 24px (`IconButton` Padding 8→5.6 + иконка 13) — следующая по высоте.
3. **Шрифты строки не сжимаются**: имя 13pt (17–18px) в обоих режимах — `ApplyCompactTree`
   шрифты в строке фактически не применил (у групп шрифты сжимаются явными DataTrigger).
4. **Экспандер группы 26×26** не сжимается → компактная группа 28px.

**Решение (только WPF/MainWindow.xaml):**
1. Новый стиль `RowActionButton` (прозрачный шаблон Border+ContentPresenter, MinHeight=0) →
   звезда и булавка становятся контент-размера (14 / компакт 12).
2. `RowIconButton` (BasedOn IconButton) с DataTrigger по `CompactMode`: Padding 8→3;
   `RowActionIcon` компакт 13→12 → кнопки действий 18px.
3. Явные DataTrigger на шрифты строки: имя 13→11.5, значения 12→11 (детерминированно, как у групп).
4. Экспандер группы в `ItemContainerStyle`: компакт 26→18 (рамка 22→16, значок 12→8) → группа 20px.
5. Обычный режим не меняется (в нём доминировали кнопки действий 31px — они не тронуты).
Итог компакт: строка без тегов ≈ 20px, группа ≈ 20–22px — равны. С тегами ≈ 34px (контент).

### #300 «Баг Линукс» — значки избранного/закрепления

После фикса 0.3.9.69 наложение сохранилось (скриншот пользователя). Требуется разбор
`MainWindow.Avalonia.Tree.cs` (построение строки, индексы колонок) — причина будет уточнена

### #301 «Линукс — текущая строка» — клик выделяет копию в «Закреплённых»

Фикс 0.3.9.70 (туннель + локальная IsSelected) не сработал у пользователя. Резервный путь —
**устранить дублирование данных**: в узле «Закреплённые» класть объекты-обёртки (не сами
`Infobase`), чтобы каждый элемент данных встречался в дереве один раз — тогда штатный
механизм выделения Avalonia физически не может подсветить чужую копию. Окончательное решение —
по результатам исследования кода.

## Стратегия

Каждый issue исправляется отдельной микро-версией (0.3.9.x) либо единым бампом до
`0.3.9.0` с перечислением всех правок. **Выбран единый бамп `0.3.9.0`** (более одного
функционального изменения → минорная версия по SemVer), с отдельными записями в
`CHANGELOG.md` по каждому issue и одним релизом. После каждого issue — комментарий
в GitHub «Исправлено в 0.3.9.0: <описание>». Issues не закрываем (требование пользователя).

> Примечание: прежние микро-версии (0.3.8.26…) делались точечно; здесь сводим правки
> в один минорный релиз для удобства сборки/выкладки, как это делалось ранее
> (см. сведение истории в `CHANGELOG.md`).

## Детализация правок по issue

### 1. #260 — двойной вопрос при закрытии окна детекта (Linux/Avalonia)
Файлы: `Configuration Management/Views/DetectConfigurationsWindow.Avalonia.cs`
- Сейчас `Closing += (_, _) => OnClosingConfirm();`, а `OnClosingConfirm()` НЕ отменяет
  закрытие. При «Нет» окно всё равно продолжает закрываться, повторно вызывая вопрос.
- Правка: обработчик должен принимать `WindowClosingEventArgs e` и при отказе ставить
  `e.Cancel = true` (аналог WPF `OnClosing`, который уже корректен — ставит `e.Cancel = true`).
- Проверить, что при подтверждении («Да») ставится `_closeConfirmed = true` и окно закрывается.

### 2. #254 — вертикальное выравнивание строк в окне детекта (Windows/WPF)
Файлы: `Configuration Management/Views/DetectConfigurationsWindow.xaml` (+ `.xaml.cs`)
- Разобраться, почему правка 0.3.8.26 (`VerticalContentAlignment=Center`) не дала эффекта:
  у разных элементов (CheckBox, TextBlock колонок, индикатор пароля, кнопка свойств)
  собственное `VerticalAlignment`/высота строки могут отличаться.
- Обеспечить единую осевую линию всех элементов строки (единый `VerticalAlignment`,
  одинаковая высота ячеек, согласованный `Padding`).
- Проверить на соответствие скриншоту из issue.

### 3. #252 — «скачет» список после сохранения свойств базы (Windows/WPF)
Файлы: `Configuration Management/Views/MainWindow.Tree.cs`, `MainWindow.xaml.cs`
- Сохранять вертикальный offset `ScrollViewer` до пересборки дерева и восстанавливать
  после пересборки (после сохранения свойств базы).
- Устранить «уход» списка: позиция прокрутки и выбранная строка должны сохраняться.
- Проверить, что кэш `GetTreeScrollViewer` (0.3.8.28) не конфликтует с восстановлением.

### 4. #255 — «колбасит» список при прокрутке, полоса меняет размер (Windows/WPF)
Файлы: `Configuration Management/Views/MainWindow.Scroll.cs`, `MainWindow.Columns.cs`, `MainWindow.Tree.cs`
- По анализу ksv47: главные остаточные причины —
  - `OnTreeScroll_ScrollChanged` реагирует на `ExtentWidthChange` и вызывает
    `SyncHeaderWidthWithList()` (пересчёт ширины на каждом шаге виртуализации);
  - `QueueHeaderAlign` обнуляет `_headerAlignStabilizeCount` на каждой строке;
  - отложенные `Dispatcher.BeginInvoke(() => ScrollSelectedIntoView(...))` захватывают
    ссылку на переиспользуемый контейнер.
- Правки (независимые):
  1. не вызывать `SyncHeaderWidthWithList()` на `ExtentWidthChange`;
  2. не обнулять счётчик стабилизации, если пересчёт уже в очереди; убрать вызов
     `QueueHeaderAlign` на каждый `Loaded` строки;
  3. в отложенных прокрутках захватывать данные строки, а не контейнер; склеивать
     отложенные вызовы по флагу.
- Это снизит «рывки» и стабилизирует полосу прокрутки. Полное устранение вариативной
  высоты строк (ScrollUnit) — опционально, требует замеров.

### 5. #251 — приоритет платформы для «папки» (обе платформы)
Файлы: `Configuration Management/Views/PlatformVersionPickerWindow.xaml.cs` (WPF),
`PlatformVersionPickerWindow.Avalonia.cs` (Linux), `Services/PlatformVersionService.cs`,
`Services/OneCLaunchArgumentParser.cs`
- В режиме Авто при выборе «папки» (частичная версия, не 4 числа через 3 точки)
  не подставлять разрядность x86 — чистая версия `8.х.у` без указания разрядностей.
- При переключении флажка разрядности выделение не должно смещаться с папки на полную версию.
- При открытии выбора, когда указанная версия совпадает с папкой, текущая строка должна
  указывать на папку, а не на полную версию.
- Правка выполняется симметрично на WPF и Avalonia.

### 6. #250 — двойной клик по всей колонке «Платформа» (Windows/WPF)
Файлы: `Configuration Management/Views/MainWindow.Events.cs`
- Разобраться, почему правка 0.3.8.23 (координатный поиск колонки, строки 391–406) не
  сработала: проверить `GetColumnIndexAt(ibGrid, pos.X) == PlatformVersionColumnIndex`
  — возможно, пустая область не принадлежит `InfobaseRowGrid` или индекс колонки не совпадает.
- Исправить определение колонки под курсором так, чтобы двойной клик по любой части
  колонки «Платформа» открывал выбор версии, а не запускал базу.

## 2. Суть правок по каждому issue

### ISSUE #250 — «Место для двойного клика»
Двойной клик срабатывает только по надписи в колонке «Платформа», а не по всей колонке. Правка в обработчике двойного клика строки списка.
- Область: `Views/MainWindow.Events.cs` / `MainWindow.Avalonia.Events.cs` (обработчик двойного клика / выбор платформы).

### ISSUE #251 — «Приоритет платформы для папки»
При «Авто» подстановка платформы даёт `x86`, а требуется вид без разрядности (`8.С.У`), как у родного стартера; при наличии выделенной строки-папки не перемещать выделение на точную платформу.
- Область: выбор платформы по папке (`Views/SettingsWindow.Platforms.cs` / Avalonia, либо общий резолвер платформ).

### ISSUE #252 — «Скачет список»
После сохранения свойств базы список прокручивается в непонятное место (текущая строка остаётся текущей). Нужно сохранять позицию скролла/выделения при обновлении списка.
- Область: обновление списка после правки свойств базы (`Views/MainWindow.*` / ViewModel).

### ISSUE #253 — «Простановка галочек в окне определения всех конфигураций»
Галочки по умолчанию не проставляются там, где «красным» горит Логин/пароль, хотя данные заданы. Причина: `DetectConfigRowViewModel.ComputeHasCredentials()` смотрит только `Connection` и `ConfiguratorAuth`, а индикатор в главном списке резолвит шире.
- Область: `ViewModels/DetectConfigRowViewModel.cs` — использовать единый резолвер учётных данных (как `Services/InfobaseAuthResolver.cs`) для согласованности с зелёным/красным индикатором.

### ISSUE #254 — «Визуальная часть окна определения всех конфигураций»
Элементы строки окна не выровнены по вертикали: галочки и кнопка настроек по центру, 4 колонки выше середины, индикатор пароля ниже.
- Область: `Views/DetectConfigurationsWindow.xaml` (WPF) и `Views/DetectConfigurationsWindow.Avalonia.cs` (построение строки) — единое `VerticalAlignment=Center` и одинаковые отступы по строкам.

### ISSUE #255 — «Список колбасит» (WPF)
Диагноз ksv47: многократный пересчёт раскладки списка на каждую материализацию строки, 7 независимых причин (см. комментарий).
- Область: `Views/MainWindow.xaml`, `Views/MainWindow.Scroll.cs`, `Views/MainWindow.Columns.cs` (WPF):
  1. `ReorderGridColumns` — ранний выход, если порядок уже совпадает;
  2. `QueueHeaderAlign` — не сбрасывать стабилизацию и не вызывать из `Loaded` на каждую строку;
  3. кэшировать `GetTreeScrollViewer`/`GetTreeScrollContentPresenter`;
  4. `OnTreeScroll_ScrollChanged` — не синхронизировать по `ExtentWidthChange`;
  5. `ScrollSelectedIntoView` — передавать данные строки, а не контейнер, снять старый вызов;
  6. `OnMainTree_RequestBringIntoView` — проверить `Handled` замером;
  7. фикс. высота строк или `ScrollUnit="Item"` (по решению).
- Это самый объёмный issue — вероятно отдельный релиз-коммит.

### ISSUE #257 — «3.8.10 не запускается»
Исправление уже в коде (InvariantGlobalization выключен, версии 0.3.8.21/22). **Правка кода не требуется** — только добавить комментарий в issue со ссылкой на версию фикса.

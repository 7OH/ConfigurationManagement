### 1. #371 — «Обновление — версия не распарсена» (нет комментариев)

**Суть проблемы.** При проверке обновления УПП (`УправлениеПроизводственнымПредприятием, 1.3.285.1`) программа корректно определяет ссылку `https://releases.1c.ru/project/Enterprise13`, но в логе:
`[WARN] [Updates] Каталог доступен, но версия не распарсена (len=11760): https://releases.1c.ru/project/Enterprise13`.
Парсер не извлекает версию из HTML каталога.

**Предполагаемые файлы.**
- [`Services/OneCUpdatesService.cs`](Configuration%20Management/Services/OneCUpdatesService.cs) — `ParseLatestVersionFromProjectHtml` / `ParseLatestVersion` (ветка `isProject`, строки ~376–391): разобраться, почему для `Enterprise13` HTML не распознаётся (возможно, изменилась структура таблицы `#versionsTable`, нужен `?allUpdates=true#updates` как в #352, или версия в другом элементе).
- [`ConfigurationManagement.Tests/OneCUpdatesUrlTests.cs`](ConfigurationManagement.Tests/OneCUpdatesUrlTests.cs) / новые тесты парсера на фактическом HTML-образце.

**Рекомендации.** Воспроизвести запрос каталога `Enterprise13` (с авторизацией ИТС), сохранить HTML, добавить юнит-тест парсера на этот образец; при необходимости расширить парсер (аналогично `BuildAllUpdatesCatalogUrl` из #352). Проверить, что `ParseLatestVersionFromProjectHtml` обрабатывает и полный каталог (`allUpdates=true`), и урезанный.

### 3. #367 — «Задание — проверка наличия обновления для конфигурации» (последний комментарий от 7OH)

**Суть проблемы.** Основная функциональность реализована в 0.3.12.18. Замечания репортёра:
1. Нужна **периодичность** повтора (как в 1С — «каждый час» и т.п.), а не только время+дни.
2. Результат «Выполнить сейчас» непонятен («Пока сложно понять — что это значит»): для конфигурации, где обновления точно есть, сводка неочевидна.
3. Предложения те же, что в #366 (периодичность, «Уведомлять об отсутствии»).

**Предполагаемые файлы.**
- [`Models/ScheduledTask.cs`](Configuration%20Management/Models/ScheduledTask.cs) — новые поля периодичности (интервал повторения) и опции «Уведомлять об отсутствии» (общие для #366/#367).
- [`ViewModels/ScheduledTaskEditViewModel.cs`](Configuration%20Management/ViewModels/ScheduledTaskEditViewModel.cs) — поля формы, валидация.
- Окно редактирования задания (WPF/Avalonia) — элементы управления периодичностью.
- [`Services/SchedulerService.cs`](Configuration%20Management/Services/SchedulerService.cs) — расчёт следующего запуска с учётом интервала.
- [`Services/ConfigurationUpdateCheckLogic.cs`](Configuration%20Management/Services/ConfigurationUpdateCheckLogic.cs) — понятная сводка результата, опция «не уведомлять при отсутствии обновлений».
- Локализация ru/en.

**Рекомендации.** Сначала спроектировать общую модель периодичности (общая для #366 и #367), затем реализовать в обоих типах заданий. Сводка результата должна явно говорить «Обновлений нет» / «Доступны версии: …».

### 6. #361 — «Логика показа нижних версий в Обновление платформы» (последний комментарий от 7OH)

**Предполагаемые файлы.**

- [`ViewModels/PlatformUpdateViewModel.cs`](Configuration%20Management/ViewModels/PlatformUpdateViewModel.cs) — передача полного списка установленных версий.
- Тесты: `PlatformUpdateViewModelTests.cs`, `PlatformVersionService`-тесты.

**Рекомендации.** Воспроизвести: установить платформу на диск D:, проверить, попадает ли она в список установленных. Причина, скорее всего, в `PlatformVersionService` (сканирование только `C:\Program Files\1cv8` и т.п.).

### 7. #352 — «Цепочки обновлений для базы» (последний комментарий от 7OH)

**Суть проблемы.** Большая часть реализована (0.3.9.328–0.3.12.12). Осталось по последнему комментарию:
1. **Цепочка скачивает файлы с неоригинальными именами** (`УТ 11_11.5.25.80.zip`), а одиночное скачивание уже даёт оригинальное имя (`Trade_11_5_27_98_setup1c.zip`). Нужно для цепочек тоже сохранять оригинальные имена.
2. **Окно уходит за панель задач** при появлении таблицы цепочек (после перестановок окно стало выше, но не контролируется рабочая область). Нужно контролировать, чтобы окно оставалось в пределах рабочей области (как в #368 — `WindowSizeMath.ComputeMaximizedBounds`).
3. Кнопки «Выбрать» и «Открыть» **обрезаны снизу** — поправить вёрстку панели папки цепочки.

**Предполагаемые файлы.**
- [`Services/UpdateChainDownloadPlanner.cs`](Configuration%20Management/Services/UpdateChainDownloadPlanner.cs) — имена файлов цепочки: использовать оригинальные имена дистрибутивов (как `UpdateDownloadNaming.BuildDownloadFileName`), сохранив `.download`-механику и докачку.
- [`Services/UpdateDownloadNaming.cs`](Configuration%20Management/Services/UpdateDownloadNaming.cs) — переиспользовать для цепочек.
- [`Views/UpdateCheckWindow.xaml`](Configuration%20Management/Views/UpdateCheckWindow.xaml) / [`Views/UpdateCheckWindow.Avalonia.cs`](Configuration%20Management/Views/UpdateCheckWindow.Avalonia.cs) — ограничение высоты окна рабочей областью (переиспользовать `WindowSizeMath`), вёрстка кнопок «Выбрать»/«Открыть».
- [`Services/WindowSizeMath.cs`](Configuration%20Management/Services/WindowSizeMath.cs) — при необходимости хелпер для ограничения окна рабочей областью.
- Тесты: `UpdateChainDownloadPlannerTests`, `OneCUpdatesDistributionResolutionTests`.

**Рекомендации.** Сначала имена файлов цепочки (единая логика с одиночным скачиванием), затем геометрия окна. Проверить, что докачка по-прежнему работает с новыми именами.

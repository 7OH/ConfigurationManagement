Исправлено в версии **0.3.9.243** (Windows/WPF и Linux/Avalonia) — окно «Диагностика подключения»: порт подставляется при открытии, выбор сервера с портом как при правке базы, запоминание портов в разрезе сервера и проверка хранилища 1С.

**Что было сломано/не хватало (после 0.3.9.231–232).**

1. **При старте на выбранной базе порт «помнился», но в поле не подставлялся** — цепочка `NetworkDiagnosticsTarget.FromInfobase → ViewModel → поле` обрывалась: поле порта в окне отсутствовало, порт уходил только во внутренний набор портов проверки.
2. **Не было выбора сервера с портом** (как в окне правки свойств базы).
3. **Порты не запоминались в разрезе сервера** — при каждом открытии приходилось вводить заново; на каждый сервис (кластер, rac/монитор, хранилище) должен быть свой порт.
4. **Сервер хранилища 1С отсутствовал в списке поддерживаемых сервисов** (порт по умолчанию 1542, имя, проверка).

**Как исправлено.**

1. В ViewModel добавлены свойства `Port`/`PortText`: стартовый порт берётся из цели диагностики — порт базы (`Connection.Port`) или монитора имеет приоритет над сохранённым и сразу попадает в поле ([`ViewModels/NetworkDiagnosticsViewModel.cs`](Configuration%20Management/ViewModels/NetworkDiagnosticsViewModel.cs)).
2. В окно добавлены список известных серверов 1С (`AvailableServers`/`SelectedServer`, берётся из клиент-серверных баз списка, как в окне правки базы) и поле «Порт»; при смене сервера подставляется сохранённый для него порт кластера ([`Views/NetworkDiagnosticsWindow.xaml`](Configuration%20Management/Views/NetworkDiagnosticsWindow.xaml), [`Views/NetworkDiagnosticsWindow.Avalonia.cs`](Configuration%20Management/Views/NetworkDiagnosticsWindow.Avalonia.cs)). Новые поля выровнены по центру строки команд.
3. Запоминание портов в разрезе сервера — новое хранилище [`Services/ServerPortsStore.cs`](Configuration%20Management/Services/ServerPortsStore.cs): файл `server_ports.json` рядом с настройками приложения (по образцу `deleted_groups.json`), запись «сервер → порт(ы)» на каждый сервис — кластер (поле окна), rac/монитор (агент 1540), хранилище конфигурации (1542). Порт сохраняется после проверки и подставляется при следующей смене сервера; файл можно править вручную.
4. Сервер хранилища 1С добавлен в список поддерживаемых сервисов: порт по умолчанию **1542** (`OneCPorts.Repository`), имя в таблице портов «сервер хранилища конфигурации» (ключ `Diagnostics.PortRepository`, ru/en) и кнопка **«Проверить хранилище»** (`CheckRepositoryCommand` — использует сохранённый порт хранилища или 1542). Кнопка «Проверить порты 1С» теперь проверяет 1540/1541/**1542**/1545.

**Тесты.** Юнит-тесты VM ([`NetworkDiagnosticsViewModelTests.cs`](ConfigurationManagement.Tests/NetworkDiagnosticsViewModelTests.cs)): старт с целью заполняет поле портом (порт цели приоритетнее сохранённого); смена сервера подставляет сохранённый порт; команда проверки хранилища использует порт по умолчанию/сохранённый и запоминает его. Юнит-тесты хранилища ([`ServerPortsStoreTests.cs`](ConfigurationManagement.Tests/ServerPortsStoreTests.cs)): запись/чтение, обновление записи, независимость серверов, нормализация ключей (без пробелов, регистронезависимо), битый файл, санитизация портов. Регрессия `NetworkDiagnosticsIntegrationTests`/`NetworkDiagnosticsTargetTests` без изменений. Полный прогон `dotnet test` и сборка Linux-ветки (`dotnet build -p:BuildLinux=true`) — без ошибок.

**Как проверить.**

1. Установите версию **0.3.9.243**.
2. Выделите клиент-серверную базу с портом (например, 1541) → «Утилиты → Диагностика подключения»: в поле «Порт» сразу стоит порт базы.
3. Смените сервер в списке: адрес и порт подставляются (сохранённый порт этого сервера или 1541 по умолчанию). Выполните проверку — введённый порт запомнится в `server_ports.json` рядом с настройками.
4. «Проверить хранилище»: проверяется порт 1542 (или сохранённый для этого сервера); в таблице портов сервис называется «сервер хранилища конфигурации».
5. «Проверить порты 1С»: проверяются 1540, 1541, 1542, 1545.
6. Повторите на Linux (Avalonia).

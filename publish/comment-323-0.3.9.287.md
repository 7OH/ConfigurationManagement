Исправлено в версии **0.3.9.287** (Windows/WPF и Linux/Avalonia).

**Что было:** `HTTP 302 для 'https://releases.1c.ru/project/AccountingCorp30' (requestUri=<тот же>)` — при отсутствии сессии releases.1c.ru отвечает **302 без заголовка Location** (поведение CAS Spring Security), а служба возвращала такой ответ как есть, и проверка обновлений завершалась голой технической ошибкой «HTTP 302» вместо понятного сообщения. Вторая часть (#334): «Для входа на portal.1c.ru не задан логин» + пустой ответ каталога платформы.

**Как исправлено** ([`OneCUpdatesService.cs`](Configuration%20Management/Services/OneCUpdatesService.cs)):

1. **302 без Location / циклический редирект = требование авторизации.** В [`SendWithAuthAsync`](Configuration%20Management/Services/OneCUpdatesService.cs) при 3xx без заголовка Location или редиректе на тот же адрес выполняется программный вход на portal.1c.ru (один раз за сессию службы) и повтор исходного запроса с сохранёнными cookie. Если вход невозможен (учётные данные не настроены или неверны) — проверка завершается понятной ошибкой «Нет доступа к сайту 1С: требуется вход… Проверьте учётные данные ИТС» (`Updates.AuthRequired`) вместо «HTTP 302».
2. **Диагностика.** Каждый редирект теперь логируется с номером шага и заголовком Location — по журналу видно реальный путь CAS-авторизации (куда именно ведёт 302).
3. **Обработка в `CheckForUpdatesAsync`.** Все статусы 3xx (в т.ч. 302 без Location) классифицируются как «требуется авторизация»; 401/403 — как раньше.
4. **#334 (обновление платформы).** Выбор учётной записи ИТС из настроек/справочника доходит до `GetCredentials()` (после фикса #333 пункт отображается именем, а не ключом); при отсутствии настроенных учётных данных показывается явное сообщение «Требуется вход на сайт 1С», а не голый NetworkError.

**Тесты.** [`UpdateCheckCatalogTests`](ConfigurationManagement.Tests/UpdateCheckCatalogTests.cs) дополнены: 302 без Location → `AuthRequired`; 302 на login.1c.ru → `AuthRequired`; **302 без Location → вход на portal.1c.ru → повторный запрос каталога → найдена новая версия**; зелёный путь 200 с HTML. Полный набор `dotnet test` зелёный (1591), кросс-сборка Linux (`dotnet build -p:BuildLinux=true`) без ошибок.

**Как проверить:**

1. Установите **0.3.9.287** ([релиз v0.3.9.287](https://github.com/sivatorov/ConfigurationManagement/releases/tag/v0.3.9.287)).
2. Настройте учётные данные ИТС (Настройки → Учётные данные ИТС или Утилиты → Информация → Учетные данные ИТС), если ещё не настроены.
3. F9 (проверка обновлений конфигурации) и окно «Обновление платформы 1С»: вместо «HTTP 302» должна появиться понятная ошибка авторизации либо успешный результат после автоматического входа.
4. Если снова появится ошибка — пришлите журнал: в нём теперь есть строки вида `[Updates] Редирект 302 (шаг N): '<Location>' для '<URL>'`, по которым видно реальный путь CAS.

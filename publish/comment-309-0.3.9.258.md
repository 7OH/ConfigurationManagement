Исправлено в версии **0.3.9.258** (Windows/WPF; Linux/Avalonia — там колонки строятся кодом и проблема не воспроизводилась).

Седьмая попытка по горизонтальной прокрутке: последние колонки («Конфигурация» / «№ релиза»)
должны быть достижимы при максимальном скролле, при этом ложная полоса при помещающихся
колонках не появляется (анти-регресс #255).

**Гипотеза, исправленная в этой версии.** У TreeView включены `CanContentScroll=True` и
пиксельная виртуализация (`MainWindow.xaml`): виртуализирующая панель меряется ВЬЮПОРТНОЙ
шириной, поэтому `MinWidth`, заданный только внутреннему `ScrollContentPresenter` дерева,
может не расширять `ExtentWidth` — полоса прокрутки остаётся короче суммы колонок, и правые
колонки «за краем». Именно это объясняет, почему шесть прошлых попыток (0.3.9.102–0.3.9.253)
не давали результата: все они ставили минимум на один контейнер, а не на сами строки.

**Как исправлено** ([`Views/MainWindow.Columns.cs`](Configuration%20Management/Views/MainWindow.Columns.cs)):

- жёсткий минимум (сумма всех видимых колонок) теперь дублируется на корневые Grid
  материализованных строк (`InfobaseRowGrid`/`GroupRowGrid`): `DesiredSize` панели становится
  ≥ суммы колонок, `ExtentWidth` дотягивает до конца, полоса прокрутки покрывает все колонки;
  обход строк выполняется только при фактическом изменении рассчитанной суммы (не на каждый
  `ScrollChanged`), новые виртуальные строки перекрываются ближайшим пересчётом при прокрутке;
- замер фактической ширины контента строк (`UpdateTreeMinWidthContent`) расширен с 3 до 12
  строк — широкая строка ниже первых трёх больше не остаётся без учёта;
- добавлен **инструментальный лог** `CM_COLUMNS` в журнал приложения (пишется при изменении
  рассчитанной суммы): сумма колонок, фактические ширины заголовка, замер контента,
  viewport/extent внутреннего ScrollViewer и DPI. Если проблема у вас сохранится — пришлите,
  пожалуйста, строки `CM_COLUMNS` из журнала (каталог данных приложения), и следующая итерация
  будет точечной по данным, а не по предположениям.

**Тесты.** Полный набор `dotnet test` зелёный (1473), кросс-сборка Linux без ошибок.

**Как проверить в 0.3.9.258.**

1. Установите 0.3.9.258 на Windows.
2. Включите колонки «Конфигурация» и «№ релиза» (настройки → колонки), при необходимости
   уменьшите окно так, чтобы колонки не помещались.
3. Прокрутите список вправо до упора — колонка «№ релиза» должна полностью попадать в область
   просмотра.
4. Проверьте обычный масштаб и 125/150% (Windows).
5. Если при помещающихся колонках появится лишняя горизонтальная полоса — сообщите: это
   регресс #255, будет отдельная правка.

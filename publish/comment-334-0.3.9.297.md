Исправлено в версии **0.3.9.297** (Windows/WPF и Linux/Avalonia).

**Что было сделано.**

Причина была в двух местах, и оба устранены.

1. **Учётные данные ИТС не доходили до входа на portal.1c.ru.** Сервис
   `OneCUpdatesService` создавался без справочника учётных записей — поле
   `IItsAccountsStore` было `null`, и `GetCredentials()` читал только устаревшие
   поля настроек `UpdatesLogin/UpdatesPassword`. Если они были пусты, вход даже не
   начинался: «Для входа на portal.1c.ru не задан логин» (ваша строка из лога).
   Теперь в сервис внедряется `IItsAccountsStore`, и при входе используется
   учётная запись из справочника (`its_accounts.json`, включая выбранную или
   «Основную»); старые поля настроек остались только как запасной вариант.

2. **Цепочка CAS-входа доведена до конца.** Раньше после POST формы входа при
   ответе 302 проверялось только, что Location не содержит «login», — и вход
   считался успешным, хотя GET по `security_check?ticket=…` (где выпускается
   сессионная cookie) не выполнялся. Теперь:
   - GET формы входа выполняется по полному URL редиректа (с параметром
     `service=https://releases.1c.ru/public/security_check`);
   - из формы извлекается скрытый токен `execution` (разбор расширен — в том числе
     для одинарных кавычек и другого порядка атрибутов);
   - POST логина;
   - если POST вернул 3xx, редиректы проходятся вручную до лимита шагов: GET по
     каждому Location через общий HTTP-клиент, сессионные cookie накапливаются в
     общем `CookieContainer`; цепочка считается успешной, когда получена
     200-страница вне страницы входа либо выполнен редирект на хост, отличный от
     login.1c.ru (после обязательного GET этого Location);
   - затем исходный запрос каталога повторяется.
   Вход выполняется один раз за сессию службы; защита от зацикливания — общий
   лимит шагов.

3. **Пошаговая диагностика в журнале.** Перед входом пишется имя учётной записи
   без пароля (`ResolveAccountName`: имя записи из справочника, иначе «Основная»,
   иначе «не задана»); каждый шаг цепочки — `[Updates] Редирект входа {status}
   (шаг N): '<Location>'`; результат — `[Updates] Вход на portal.1c.ru выполнен
   (шагов: N)` или понятное сообщение о неудаче (статус и Location).

**Тесты.** Добавлены тесты `UpdateCheckCatalogTests` и `PlatformDownloadViewModelTests`:
учётка из store используется при запросе кредов даже при пустых старых настройках;
фолбэк на старые настройки при пустом справочнике; полный сценарий «302 на
login.1c.ru → форма → POST → 302 на security_check?ticket=… → GET → 200 → каталог
получен» (с проверкой, что POST ушёл с логином из store); явная проверка следования
за редиректом после POST; при отсутствии кредов — понятная ошибка AuthRequired.
Существующие тесты сценариев 302 продолжают проходить.

**Как проверить:**

1. Установите версию **0.3.9.297**.
2. В «Общих настройках» добавьте учётную запись ИТС (или задайте её «Основной»);
   старые поля логина/пароля в настройках можно оставить пустыми.
3. Откройте «Обновление платформы 1С»: каталог версий должен загрузиться.
4. В журнале приложения должны быть видны имя учётной записи и шаги входа
   (`Вход на portal.1c.ru выполнен`).

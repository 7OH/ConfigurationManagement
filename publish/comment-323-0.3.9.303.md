Исправлено в версии **0.3.9.303**.

**Причина.** Окно «Проверка обновлений» (F9) давало лог «Превышен лимит попыток входа на
portal.1c.ru за сессию (лимит 3)» → «Редирект 302 (шаг 0)» → «Требуется вход на
portal.1c.ru». Общий корень с issues #334/#330 — программный вход в CAS `portal.1c.ru`:

1. **«Фантомный успех»**: любой ответ 2xx после POST входа считался успехом, хотя при
   неверном логине CAS возвращает HTTP 200 с телом формы входа (execution/lt) и без
   сессионной cookie — следующий запрос снова 302 на login → повторный вход → лимит.
2. **Счётчик попыток не сбрасывался при успехе** (служба — singleton), поэтому после
   нескольких операций вход блокировался до перезапуска приложения.
3. **Цикл 302→вход→302 внутри одного вызова** мог потратить весь лимит за одну проверку.
4. **Страница входа при HTTP 200 не распознавалась** по содержимому — вместо понятной
   ошибки авторизации пользователь видел «каталог доступен, но версия не распарсена».

**Что сделано** (в [`OneCUpdatesService.cs`](Configuration%20Management/Services/OneCUpdatesService.cs)):

1. Успех входа подтверждается содержимым тела (`LooksLikeLoginForm`): 200 с формой входа →
   честный `AuthFailed`, попытки не тратятся на «фантомный успех».
2. Счётчик попыток сбрасывается во всех ветках успеха; ранний выход по сессионной cookie
   (`HasPortalSessionCookie`, JSESSIONID/TGC/session_id).
3. Не более одной попытки входа за вызов (`loginTried` в `SendWithAuthAsync`).
4. `CheckForUpdatesAsync` распознаёт страницу входа при HTTP 200 по содержимому и возвращает
   ключ `Updates.AuthRequired`/`Updates.AuthFailed`; окно F9 показывает уточнённые тексты
   ошибок с советом проверить учётные данные ИТС.
5. Лимит: понятное сообщение («Проверьте учётные данные ИТС… при неверном пароле портал
   может временно блокировать аккаунт»), автосброс через ~10 минут и отдельный ключ
   локализации `Updates.LoginLimitReached`.

Тесты: 7 новых сценариев + 2 обновлённых в
[`OneCUpdatesLoginFlowTests.cs`](ConfigurationManagement.Tests/OneCUpdatesLoginFlowTests.cs);
полный набор **1717** тестов зелёный, кросс-сборка Linux без ошибок.

**Как проверить:**

1. «Проверка обновлений» (F9) с корректными учётными данными ИТС — результат получен с
   первой попытки, без «Превышен лимит» и без «Редирект 302 (шаг 0)» при отсутствии
   реальной причины.
2. Повторные проверки разных баз не упираются в лимит (счётчик сбрасывается при успехе).

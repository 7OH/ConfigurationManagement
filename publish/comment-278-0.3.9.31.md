Исправлено в версии 0.3.9.31.

Причина: в двустороннем режиме синхронизация всегда шла «сначала выгрузка, потом загрузка». После ручного восстановления ibases.v8i выгрузка первой сопоставляла запись по ID 1С, переименовывала её обратно в имя из приложения (« 2») и записывала в файл, а загрузка читала уже перезаписанный файл — поэтому « 2» оставалось и в приложении, и в списке баз.

Что сделано:
- Приложение запоминает момент своей последней выгрузки в ibases.v8i.
- В двустороннем режиме сравнивается время последнего изменения файла с моментом последней выгрузки приложения: если файл менялся после нашей последней записи (например, вы восстановили его вручную), сначала выполняется ЗАГРУЗКА из файла, затем выгрузка — имя базы возвращается из файла и обратно в файл не записывается. Если файл не менялся — порядок прежний (выгрузка, затем загрузка).
- Метка обновляется при любой выгрузке: автосинхронизация, кнопка «Выгрузить», «Сохранять после правки».

Проверено тестами: выбор порядка по датам (файл новее → загрузка первой), метка обновляется после выгрузки, повторная синхронизация не плодит дубли.

Обновитесь до 0.3.9.31. Если сценарий всё ещё воспроизводится — опишите точные шаги, продолжим разбирать.

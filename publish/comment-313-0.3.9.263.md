Исправлено в версии **0.3.9.263** (Windows/WPF и Linux/Avalonia). Продолжение фиксов 0.3.9.114 и 0.3.9.239 — теперь по вашему предложению из комментария 7OH.

**Что было не так.**

После фиксов правого клика (набор «для выделенных» больше не меняется на правой кнопке) остался ровно тот сценарий, что вы описали:

1. Первую строку делаем просто текущей — обычный клик БЕЗ Ctrl.
2. Ctrl-кликами помечаем 2-ю и 3-ю строки.
3. Правый клик по строке набора — в контекстном меню блок «Для выделенных (N)…» показывает меньше баз, чем ожидалось: первая («просто текущая») из набора пропадает.

**Причина.**

«Просто текущая» строка (последняя выбранная обычным кликом без Ctrl) в набор мультивыделения не входила — она только «якорь» для Shift-диапазона. Правый клик набор не меняет намеренно (фиксы 0.3.9.114/0.3.9.239), поэтому строка, которая не была помечена Ctrl, так и оставалась вне набора — «терялась» из меню.

**Как исправлено** (по вашему предложению: «при клике с контролом не на текущей строке, ставить внутреннюю галку выделения текущей строке тоже»).

Семантика первого Ctrl-клика стала как в проводнике: если набор пуст и Ctrl-клик приходится на строку, отличную от «текущей», в набор добавляются и «текущая», и целевая. Если Ctrl-клик по самой «текущей» — она просто помечается (как раньше). Повторный Ctrl-клик по строке набора — прежнее снятие (toggle). Обычный клик по-прежнему сбрасывает набор.

Правило секций (закрепления vs обычный список, issue #326) соблюдается: «текущая» добавляется только если она лежит в той же секции дерева, что и цель — закреплённые и обычные строки в одном наборе не смешиваются.

Файлы:

- [`BatchSelectionHelper.ApplyModifiedClick`](Configuration%20Management/Services/BatchSelectionHelper.cs) — новые параметры `includeId`/`includeSectionIsPinned`: добавление «текущей» при первом Ctrl-клике (чистая логика, тестируется);
- [`MainViewModel.Batch.cs`](Configuration%20Management/ViewModels/MainViewModel.Batch.cs) — `ToggleBatchSelection` передаёт `SelectedInfobase` как «текущую» и признак её секции;
- WPF [`MainWindow.Events.cs`](Configuration%20Management/Views/MainWindow.Events.cs) и Avalonia [`LeveledTreeView.Avalonia.cs`](Configuration%20Management/Controls/LeveledTreeView.Avalonia.cs) — признак секции «текущей» строки из данных её контейнера (`PinnedInfobaseItem` для закреплённой копии).

Правый клик по-прежнему набор не меняет — теперь это безопасно, потому что «текущая» попадает в набор уже на первом Ctrl-клике.

**Тесты.**

[`BatchSelectionHelperTests`](ConfigurationManagement.Tests/BatchSelectionHelperTests.cs): первый Ctrl-клик по строке ≠ текущей → набор {текущая, цель}; Ctrl-клик по самой текущей → только она; непустой набор → прежний toggle (без повторного добавления); разные секции → текущая не добавляется; регрессия полного сценария (обычный клик → Ctrl+2, Ctrl+3 → правый клик — все три строки в «Для выделенных»). Полный набор `dotnet test` зелёный (1488), кросс-сборка Linux (`dotnet build -p:BuildLinux=true`) без ошибок.

**Как проверить в 0.3.9.263.**

1. Установите версию 0.3.9.263.
2. Обычный клик по первой базе (без Ctrl) — она просто текущая.
3. Ctrl+клик по 2-й строке — в набор попадают и 1-я («текущая»), и 2-я.
4. Ctrl+клик по 3-й строке — в наборе 1, 2, 3.
5. Правый клик по 3-й строке — блок «Для выделенных (N)…» показывает 3 базы (1-я не теряется).
6. Ctrl+клик по строке из закреплений при «текущей» в обычном списке — набор в закреплениях начинается без «текущей» (секции не смешиваются).
7. Повторите на Linux (Avalonia).

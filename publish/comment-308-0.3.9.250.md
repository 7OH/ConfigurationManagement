Исправлено в версии **0.3.9.250** (Windows/WPF и Linux/Avalonia) по последним замечаниям к issue.

**1. «Уведомлять о запуске» вместо обязательного окна «скрипт запущен».**

В редакторе сценария добавлена галочка **«Уведомлять о запуске»** (в строке с «Интерпретатор», рядом со «Скрывать окно скрипта»):

- при **выключенной** (по умолчанию для новых сценариев) окно «скрипт запущен» больше не показывается и **системные уведомления о запуске не отправляются** — «без опций — просто не надо»;
- при **включённой** — прежнее поведение: диалог с командной строкой + системное уведомление (для случая, когда приложение свёрнуто в трей);
- старые сценарии без нового поля мигрируют без ошибок (флаг выключен).

**2. Окно редактора сценария стало выше и не уходит за рамки экрана.**

Высота увеличена (WPF: 640→720, Avalonia: 680→720). После показа окно подгоняет высоту под содержимое и ограничивается рабочей областью экрана через общий чистый `Services/WindowSizeMath.cs` (`ClampHeight`/`FitTop`) — как в остальных окнах приложения (ConfigDiffSetupWindow, CreateInfobaseWindow). На маленьких экранах окно поднимается, чтобы нижняя часть не уходила за край.

**3. «Не закрывать» — окно скрипта остаётся открытым после завершения.**

Возле «База для примера подстановок» добавлена галочка **«Не закрывать»**. При включённой к командной строке добавляется хвостовая команда, удерживающая консольное окно при ошибках и завершении, в зависимости от выбранного интерпретатора:

| Интерпретатор | Хвост |
|---|---|
| cmd | `& pause` |
| PowerShell | `; Read-Host` |
| sh | `; read` |

Для cmd используется безусловный разделитель `&`, для PowerShell/sh — `;`, поэтому окно удерживается **и при ошибке** скрипта (не только при успешном завершении). Превью командной строки в редакторе и окне выбора учитывает флаг — хвост виден сразу.

Тесты: построение команды с хвостом удержания для cmd/PowerShell/sh и режима «Авто» (обе платформы); перенос флагов «Уведомлять о запуске»/«Не закрывать» формой и дефолты новых сценариев. Полный прогон `dotnet test` зелёный (1449), `dotnet build -p:BuildLinux=true` без ошибок.

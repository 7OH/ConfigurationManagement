Исправлено в версии 0.3.9.33 (Linux/Avalonia).

**Причина**: на Linux закрытие подсказок по ESC было реализовано слабее, чем на Windows: главное окно отслеживало открытые подсказки глобально, а диалоги полагались только на обход своего визуального дерева — если владелец подсказки не находился, первый ESC закрывал диалог целиком. Диагностический трейс `CM_TOOLTIP_TRACE=1` существовал только в Windows-части, поэтому лог на Linux не создавался.

**Что сделано**:
- Общий механизм для Avalonia: открытые подсказки отслеживаются глобально во всех окнах; первый ESC в любом окне закрывает подсказку (и пользовательские Popup/контекстные меню) и не трогает окно, повторный ESC закрывает окно.
- `CM_TOOLTIP_TRACE=1` теперь работает и на Linux: лог `cm_tooltip_trace.log` пишется в каталог временных файлов (`/tmp`, учитывается `TMPDIR`). Запустите:

```bash
CM_TOOLTIP_TRACE=1 ./ConfigurationManagement
```

и приложите содержимое `/tmp/cm_tooltip_trace.log`, если проблема останется.

Обновитесь до 0.3.9.33. Если подсказки всё ещё не закрываются по ESC в каком-то окне — приложите трейс-лог, продолжим разбирать.

Исправлено в версии **0.3.9.160** (Windows/WPF и Linux/Avalonia).

**Что было сломано.** Окно «Типовые конфигурации» (Утилиты → Типовые конфигурации) имело четыре
проблемы:

1. **Не хватало подписей** — было непонятно, что это за окно и для чего оно нужно.
2. **«При попытке сохранить изменения цифры из строк попадают в другие базы или показывают
   совсем не те данные»** — при правке предопределённой конфигурации (например «Бухгалтерия
   предприятия») изменялись общие внутренние экземпляры встроенного набора, которые
   используются всеми окнами проверки обновлений: изменённые номера редакций/релизов тут же
   «расползались» по «Актуальным релизам», проверке F9 и окну «Связать с конфигурацией».
3. **Правка «два в одном»** — кнопка «Правка» разворачивала редактор прямо в окне списка;
   после неё «Закрыть» закрывал всё окно, а не только редактор. Кнопки «Добавить»/«Удалить»
   фактически не работали для пользовательских конфигураций (изменения после перезапуска
   исчезали), потому что хранилище было общим файлом настроек и редактировались встроенные
   строки, а не пользовательские.
4. **Хранение в общем файле настроек** — невозможно было поправить список вручную и передать
   другому.

**Причины.**

1. В окне отсутствовали поясняющие тексты и указание, какие конфигурации можно менять.
2. Предопределённые конфигурации из `BuiltInConfigTypes` — общие изменяемые экземпляры,
   а кнопка «Правка» была доступна и для них: изменения записывались прямо в эти экземпляры
   и были видны во всех окнах, использующих список типовых конфигураций.
3. Редактор был встроен в окно списка («два в одном»): переключение видимости панелей, Esc и
   «Закрыть» закрывали всё окно.
4. Пользовательские конфигурации хранились в `AppSettings.CustomConfigTypes` (общий
   `settings.json`), сохранение происходило только при закрытии окна, а добавляемые записи
   часто оказывались правками встроенных строк.

**Как исправлено.**

- **Отдельное окно правки.** Кнопки «Изменить»/«Добавить» открывают отдельное модальное окно
  `ConfigTypeEditWindow` (код, наименование, сегмент URL, ник на releases.1c.ru, редакции).
  Правка ведётся на копии данных и применяется к строке только при нажатии «Сохранить»;
  «Отмена» ничего не меняет. «Закрыть» закрывает только окно списка. Окно «Типовые
  конфигурации» стало списком: предопределённые конфигурации отображаются только для чтения
  (кнопки «Изменить»/«Удалить» для них скрыты) — это исключает случайную порчу встроенных
  данных, которая и приводила к «перепутанным» цифрам.
- **JSON-хранилище.** Пользовательские конфигурации теперь хранятся в отдельном читаемом
  файле **`custom_config_types.json`** рядом с настройками приложения (UTF-8, без
  `\uXXXX`-экранирования). Файл можно править вручную и передавать другим. Существующие
  пользовательские конфигурации из старых настроек переносятся автоматически при первом
  запуске (идемпотентно, старые настройки не изменяются). Сохранение выполняется сразу при
  добавлении/правке/удалении — изменения переживают перезапуск.
- **Единый список типовых.** Все потребители («Актуальные релизы», проверка обновлений F9,
  окно «Связать с конфигурацией») читают список через один загрузчик
  (`ICustomConfigTypesStore.LoadAll()` = встроенные + пользовательские) — расхождений между
  окнами больше нет.
- **Подписи и пояснения.** В окне добавлены описание назначения (каталоги релизов обновлений
  1С для проверки обновлений и «Актуальных релизов»), пометка предопределённых конфигураций
  (★, изменение недоступно) и указание, где лежит файл пользовательских конфигураций.

**Как проверить.**

1. Установите версию **0.3.9.160** (Windows или Linux).
2. Откройте «Утилиты → Типовые конфигурации»: видны пояснения, предопределённые строки
   помечены ★ и не имеют кнопок «Изменить»/«Удалить».
3. Нажмите «Добавить конфигурацию»: откроется отдельное окно; заполните наименование
   (и при необходимости сегмент URL, ник, редакции) и нажмите «Сохранить» — строка появится
   в списке. Закройте окно списка и откройте его снова — конфигурация на месте.
4. Нажмите «Изменить» у пользовательской конфигурации, поменяйте номера редакций, сохраните:
   в «Актуальных релизах» (Alt+F9) и при проверке обновлений (F9) для этой конфигурации
   показываются только её данные; у соседних строк ничего не меняется.
5. Попробуйте «Удалить» у пользовательской конфигурации — подтверждение, строка исчезает и
   не возвращается после перезапуска. У предопределённых такой кнопки нет.
6. Проверьте файл `custom_config_types.json` рядом с настройками приложения: он читаемый,
   кириллица не экранирована; можно поправить значения вручную и перезапустить приложение —
   изменения подхватятся.
7. Если раньше пользовательские конфигурации уже были добавлены — при первом запуске они
   автоматически перенесутся из старых настроек в новый файл (без дублей).

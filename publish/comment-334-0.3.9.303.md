Исправлено в версии **0.3.9.303**.

**Причина.** Автообновление платформы (и другие операции с порталом) давали
«Превышен лимит попыток входа на portal.1c.ru за сессию (лимит 3)» → «Редирект 302
(шаг 0)» → «каталог не получен — PlatformUpdate.Error.AuthRequired». Общий корень —
CAS-авторизация на `portal.1c.ru`:

1. **«Фантомный успех»**: любой ответ 2xx после POST входа считался успехом. При неверном
   логине CAS возвращает HTTP 200 с телом формы входа (поля `execution`/`lt`) и **без**
   сессионной cookie — следующий запрос каталога снова даёт 302 на login → повторный вход
   ×3 → лимит исчерпан.
2. **Счётчик попыток не сбрасывался при успехе** (служба — singleton), поэтому после
   нескольких операций вход блокировался намертво до перезапуска.
3. **Цикл 302→вход→302 внутри одного вызова** мог потратить весь лимит за одну операцию.
4. **Страница входа при HTTP 200 не распознавалась** по содержимому — ответ уходил в
   парсинг каталога и давал непонятную ошибку.

**Что сделано** (в [`OneCUpdatesService.cs`](Configuration%20Management/Services/OneCUpdatesService.cs)):

1. Успех входа теперь подтверждается содержимым тела (`LooksLikeLoginForm`): 200 с формой
   входа → честный `AuthFailed` с анонимизированной диагностикой, без траты оставшихся
   попыток на «фантомный успех».
2. Счётчик попыток сбрасывается во всех ветках успеха; ранний выход по сессионной cookie
   (`HasPortalSessionCookie`, JSESSIONID/TGC/session_id).
3. Не более одной попытки входа за вызов (`loginTried`).
4. `FetchPageCoreAsync`/`CheckForUpdatesAsync` распознают страницу входа по содержимому при
   HTTP 200 и возвращают понятную ошибку авторизации.
5. Лимит: понятное сообщение («Проверьте учётные данные ИТС в «Настройки → Учётные данные
   ИТС»… при неверном пароле портал может временно блокировать аккаунт»), автоматический
   сброс через ~10 минут и отдельный статус/ключ локализации `LoginLimitReached`
   (окна обновления платформы и проверки обновлений показывают совет).

Тесты: 7 новых сценариев + 2 обновлённых в
[`OneCUpdatesLoginFlowTests.cs`](ConfigurationManagement.Tests/OneCUpdatesLoginFlowTests.cs);
полный набор **1717** тестов зелёный, кросс-сборка Linux без ошибок.

**Как проверить:**

1. «Обновление платформы 1С» (Ctrl+F9) с корректными учётными данными ИТС — каталог
   получается с первой попытки, в журнале нет «status=200» фантома и «Превышен лимит».
2. Тот же сценарий с неверным паролем — понятное «вход не подтверждён», не более 3 попыток,
   через ~10 минут можно повторить.
3. Повторные операции (проверка каталога + подгрузка файлов релиза) больше не упираются
   в лимит.

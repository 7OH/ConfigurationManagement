Исправлено в версии **0.3.9.300** по последним замечаниям.

**Что было.**

После мультивыделения, правого клика (контекстное меню) и левого клика по другой строке выделение сначала применялось, а затем через мгновение пропадало. Три предыдущие попытки (0.3.9.277, 0.3.9.291, 0.3.9.299) подавляли повторную доставку клика флагом/отложенным применением выбора — проблема сохранялась.

**Что сделано.**

Применён новый механизм: клик, которым закрыли контекстное меню, вообще не доходит до дерева как новое действие выбора — вместо подавления «по флагу» используется дедупликация по данным события.

1. В момент, когда попап контекстного меню захватил мышь, запоминается «исходный клик» — `(кнопка, время MouseDown, координаты)`.
2. В обработчике дерева `OnInfobaseTree_PreviewMouseLeftButtonDown` событие, совпадающее с исходным кликом (допуск ~300 мс по времени, позиция в пределах строки), помечается обработанным **без применения выбора** — строка не активируется, текущее выделение не трогается.
3. Выбор строки применяется однократно по данным реального `MouseDown`. Помощник дедупликации вынесен в чистый [`BatchSelectionHelper.IsSameClick`](Configuration%20Management/Services/BatchSelectionHelper.cs) (время + позиция, допуски по времени и координатам); отложенный повтор `TryApplyTreeClickAfterMenuClosed` и флаг подавления удалены.
4. Тот же механизм на Linux/Avalonia (`MainWindow.Avalonia.Events.cs` / `MainWindow.Avalonia.Hotkeys.cs` — дедупликация `PointerPressed`/`PointerReleased` по времени и позиции).

**Тесты** ([`BatchSelectionHelperTests.cs`](ConfigurationManagement.Tests/BatchSelectionHelperTests.cs)): `IsSameClick` (совпадение/различие по времени и позиции), выбор применяется один раз по данным последнего `MouseDown`.

**Как проверить:** обновитесь до **0.3.9.300**; выделите несколько строк → правый клик → клик по другой строке: новая строка остаётся активной, выделение не пропадает. Простой кейс: контекстное меню по строке → клик по другой строке → строка остаётся активной.

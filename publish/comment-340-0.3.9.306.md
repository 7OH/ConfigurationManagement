Исправлено в версии **0.3.9.306** (Windows/WPF и Linux/Avalonia; восьмая попытка исправления).

**Что было.**

«Не помогло» — проблема сохранялась после семи попыток (0.3.9.277, 0.3.9.291, 0.3.9.299, 0.3.9.300, 0.3.9.302, 0.3.9.304, 0.3.9.305): выделение пропадает после закрытия контекстного меню при клике мышью на другой строке. Диагностика `CM_MENUCLOSE_TRACE=1` из 0.3.9.305 лог-файл **не создала**: переменная окружения не была выставлена (в GUI-окружении Windows это нетривиально), а путь `%TEMP%` у пользователя мог отличаться. Просьба — писать трассировку в файл рядом с настройками приложения.

**Что сделано.**

1. **Диагностика заменена** ([`Services/MenuCloseTrace.cs`](Configuration%20Management/Services/MenuCloseTrace.cs)): env-переменная и `%TEMP%` убраны; трассировка пишется **всегда** в файл **`menuclose_trace.json`** рядом с настройками приложения: Windows — `%APPDATA%\ConfigurationManagement\menuclose_trace.json`, Linux — `~/.config/ConfigurationManagement/menuclose_trace.json` (тот же каталог, где лежат `settings.json` и пр.). Формат — JSON Lines (одна JSON-запись на строку); файл автоматически усекается при превышении ~512 КБ (остаётся хвост последних записей); при запуске пишется стартовая запись с версией приложения и платформой. Сериализация/усечение вынесены в новый [`Services/MenuCloseTraceFormat.cs`](Configuration%20Management/Services/MenuCloseTraceFormat.cs). От пользователя ничего включать не нужно — файл создаётся сам.
2. **Стабилизация выбора доработана** (обе платформы, симметрично):
   - «догоняющее» восстановление выделения: если контейнер целевой строки не реализован виртуализацией (`VirtualizingStackPanel`, `Recycling`) — выбор применяется повторно через ~800 мс при появлении контейнера ([`Views/MainWindow.Tree.cs`](Configuration%20Management/Views/MainWindow.Tree.cs), зеркально Avalonia);
   - окно стабилизации расширено до **15 проходов / 1,5 с** (раньше 10 проходов / 1 с);
   - при деактивации окна сброс pending-состояния откладывается на grace-период ~300 мс: если окно снова активно (кратковременная деактивация попапом меню) — сброс не выполняется ([`Views/MainWindow.xaml.cs`](Configuration%20Management/Views/MainWindow.xaml.cs), зеркально Avalonia);
   - в трассу добавлены `IsVisible`/`IsActive`/`openMenusCount`/`selectedItemId`/`timeSinceStartMs`.
3. **Тесты**: новый [`MenuCloseTraceFormatTests.cs`](ConfigurationManagement.Tests/MenuCloseTraceFormatTests.cs) (10 тестов: валидность JSON-строки, усечение с маркером, стартовая запись, отсутствие секретов), дополнен [`BatchSelectionHelperTests.cs`](ConfigurationManagement.Tests/BatchSelectionHelperTests.cs) (4 теста). Всего **1754** теста на момент задачи #340 (полный набор 0.3.9.306 — 1759).

**Как проверить:** обновитесь до **0.3.9.306**; воспроизведите сценарий: мультивыделение (Ctrl/Shift) → правый клик (контекстное меню) → левый клик по другой строке. После проверки пришлите файл `menuclose_trace.json` (он создаётся сам, включать его нигде не нужно). Если баг сохранится — по логу будет точно видно, какое звено рвётся: путь применения клика (A/B/C), реализация контейнера, деактивация окна.

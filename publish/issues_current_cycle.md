### [#347 — «Сказ о trace.json»](https://github.com/sivatorov/ConfigurationManagement/issues/347)
- Автор: **7OH**; создан 2026-10-05T14:06:09Z; комментариев: **0**.
- Суть описания: предложение архитектуры отладочной трассировки через файл **`trace.json` рядом с настройками в профиле** (флаг-конфигуратор):
  - `"CM_COLUMNS": true` — включает записи о размерах колонок (сейчас логирование ширины колонок «капает», отключить нельзя; тикет по колонкам закрыт, а логи остались);
  - `"CM_MENUCLICK"` — отладка по кликам правой кнопкой (вынести из #340);
  - в будущем: при проблеме в тикете в обновлении появляется **выключенный** флажок, пользователь включает его по инструкции из тикета и присылает новые строки логов;
  - туда же предлагается добавить новый флажок для проверки редиректа (общий для трёх тикетов #323/#330/#334), чтобы после выяснения можно было отключить.
- **Обоснование категории А**: ни одного комментария; источник требований — только описание. Issue напрямую связан с #340 (та же трассировка кликов) и с CAS-тикетами (общий флаг диагностики редиректа).
- **Решение для следующей задачи**: первичный разбор описания, проработка формата `trace.json` (имя файла, каталог, список флажков, семантика «файл существует → флаги внутри»), определение объёма (это инфраструктурная задача-предложение, затрагивает трассировку MenuCloseTrace/кликов и логирование ширин колонок).

Это материал для анализа и, вероятно, точечных правок (например, передача `SERVERID` вместе с `JSESSIONID`, точная последовательность 4 запросов).

Исправлено в версии **0.3.9.268** (Windows/WPF и Linux/Avalonia).

**Что сделано по вашему замечанию к окну «Проверка обновлений» (F9): адрес каталога релизов теперь кликабельный.**

1. **Клик по адресу открывает браузер.** Если у конфигурации задан валидный http/https-адрес каталога релизов, он показывается как ссылка (акцентный цвет, подчёркивание, курсор-рука): клик открывает `releases.1c.ru/project/<ник>` в браузере по умолчанию — удобно для ручной проверки. Наведение показывает подсказку «Открыть каталог релизов».
2. **Ссылка активна только для настоящего адреса.** Если адреса нет (база не связана с типовой конфигурацией либо у конфигурации не задан ник) — вместо ссылки остаётся обычный вторичный текст «—», клик ничего не делает.
3. **Копирование и перенос текста сохранены.** Адрес по-прежнему выделяется и копируется как обычный текст; длинный адрес переносится по ширине окна.
4. **Единое открытие браузера на обеих платформах.** Открытие идёт через общий механизм запуска приложения (`OneCLauncher.OpenUrl`): на Windows — системный вызов браузера, на Linux — `xdg-open`, как и остальные ссылки приложения.

Файлы:

- WPF [`Views/UpdateCheckWindow.xaml`](Configuration%20Management/Views/UpdateCheckWindow.xaml) и [`Views/UpdateCheckWindow.xaml.cs`](Configuration%20Management/Views/UpdateCheckWindow.xaml.cs) — адрес выводится через `Hyperlink`; валидность проверяется (`Uri.TryCreate`, только http/https);
- Avalonia [`Views/UpdateCheckWindow.Avalonia.cs`](Configuration%20Management/Views/UpdateCheckWindow.Avalonia.cs) — ссылка-`TextBlock` (подчёркивание, курсор-рука, обработчик `PointerReleased` с проверкой попадания);
- [`Services/OneCLauncher.cs`](Configuration%20Management/Services/OneCLauncher.cs) — на Windows добавлен общий хелпер `OneCLauncher.OpenUrl(url)` (зеркало уже существовавшего метода Linux-версии), чтобы обе платформы открывали URL единообразно;
- локализация не менялась: использованы существующие ключи (`Updates.OpenCatalog` — подсказка, `Settings.About.LinkOpenFailed` — сообщение при неудаче открытия).

**Тесты.** Полный набор `dotnet test` зелёный (**1523**), кросс-сборка Linux (`dotnet build -p:BuildLinux=true`) без ошибок. Регрессия покрыта существующими тестами построения URL каталога релизов; поведение ссылки проверяется вручную.

**Как проверить в 0.3.9.268.**

1. Выделите базу → F9 («Проверка обновлений»). После проверки адрес каталога релизов — кликабельная ссылка; наведите — подсказка «Открыть каталог релизов».
2. Кликните по адресу — браузер откроет `releases.1c.ru/project/<ник>` (потребуется вход на сайт 1С).
3. Для базы без связи с типовой конфигурацией адрес остаётся текстом «—», ссылка неактивна.

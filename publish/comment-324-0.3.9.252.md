Исправлено в версии **0.3.9.252** (Windows/WPF и Linux/Avalonia).

Разбор ситуации «в терминале rac работает, а монитор данные кластера не видит» и ответ на вопрос
про порт по умолчанию.

**Порт по умолчанию 1540 — это правильно.**

- **1540** — порт **агента сервера 1С (ragent)**. Именно к нему подключается утилита `rac`:
  формат `rac <host>:<port> <команда>` (по умолчанию `localhost:1540`). Агент уже знает все
  кластеры сервера и их порты, поэтому дальше раc работает через него.
- **1541** — порт **самого кластера** (рабочего процесса rphost). Его в командной строке rac
  указывать **не нужно**: кластер выбирается параметром `--cluster=<uuid>`, а его порт приходит
  в выводе `cluster list` (колонка `port`) и показывается в списке кластеров окна монитора.
- **1545** — порт сервера администрирования **RAS** (если включён отдельный сервис).

Окно монитора предзаполняет **1540** (`IRacClient.DefaultPort`), а не 1541. Если у вас rac
подключался к серверу «напрямую по 1541» — уточните, пожалуйста, как именно выглядела рабочая
команда из терминала (полный текст, желательно из журнала приложения, см. ниже): для стандартной
схемы это `rac.exe srv1:1540 cluster list`. Подсказка о разнице портов добавлена в само окно
(всплывающая подсказка у поля «Порт» и общая строка подсказки).

**Что проверено и усилено в этой версии:**

1. **Точка подключения — единый токен `host:port`.** Все команды rac собираются как
   `rac.exe host:port …` (без раздельных `--host=`/`--port=`, которые новые версии платформы не
   разбирают). Это было заложено ещё в 0.3.9.157 и теперь зафиксировано юнит-тестами сборки
   аргументов, включая `cluster info --cluster=<uuid>`.
2. **Парсер вывода устойчив к изменённому формату.** Таблицы по-прежнему разбираются по
   табуляции (штатный формат rac), но если в выводе табуляций нет (выравнивание пробелами —
   бывает при перенаправлении/определённых окружениях), поля разделяются по 2+ пробелам, при
   этом одиночный пробел внутри значения (имя кластера) сохраняется. Парсер `cluster list/info`
   покрыт тестами на фактическом образце вывода.
3. **Логирование полной команды rac (без секретов).** В журнал приложения пишется:
   - путь к найденному исполняемому файлу rac (`rac=…`);
   - полная командная строка с замаскированным паролем (`--password=***`);
   - после выполнения — код выхода и объём stdout/stderr.
   Теперь по журналу видно, какую именно команду выполнило приложение, что rac вернул
   (данные или пустой список) и с каким кодом — это позволяет один в один сравнить с рабочей
   командой из терминала.

**Как проверить в 0.3.9.252.**

1. Установите версию 0.3.9.252 (Windows или Linux).
2. Откройте «Серверы 1С» (монитор серверов): поле «Порт» предзаполнено **1540**.
3. Укажите адрес сервера, при необходимости логин/пароль администратора кластера и нажмите
   «Подключиться».
4. В списке кластеров должен появиться кластер с именем и портом (например, 1541) — это порт
   **кластера**, а не агента; его менять не нужно.
5. Вкладки «Рабочие процессы / Сеансы / Соединения / Блокировки / Информация о кластере»
   заполняются данными, как при выполнении rac в терминале.
6. Если что-то по-прежнему не так — посмотрите журнал приложения: там есть полная команда rac
   и результат её выполнения; пришлите эти строки сюда, сравним с терминалом.

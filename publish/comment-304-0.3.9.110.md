Исправлено в версии **0.3.9.110** (Windows/WPF и Linux/Avalonia). Продолжение исправления 0.3.9.101 — регресс устранён полностью.

**Что было сломано.** Сценарий «текущая версия 8.5.4 → выбрать 8.5.1 (лист или группу сборок) →
переключить фильтр разрядности на x64»: выделение «скакало» на линию 8.5 (или терялось вовсе),
результат диалога пропадал. Исправление 0.3.9.101 запоминало выбранную версию как «текущую»,
но этого оказалось недостаточно — остальные причины регресса не были устранены.

**Причины.** Их было четыре:

1. **Фильтр x64 выкидывал версии без явной метки разрядности.** `ParseVariant` для варианта
   «8.5.1» (без суффикса) возвращает x32 по умолчанию, поэтому условие «x64 или без метки»
   никогда не пропускало такие версии — выбранная «8.5.1» исчезала из дерева при фильтре x64.
2. **Поиск листа игнорировал разрядность.** `MatchesCurrent` сравнивал только версию: при двух
   сборках одной версии (x32 и x64) мог быть выбран не тот лист.
3. **Не было fallback.** Если выбранный узел отсутствовал в отфильтрованном дереве, выделение
   просто не восстанавливалось, а `_selectedVersion` уже был сброшен перестроением ItemsSource.
4. **WPF: гонка событий.** Восстановление выбора шло через `BeginInvoke(Loaded)`, а между
   установкой ItemsSource и восстановлением приходил `SelectionChanged(null)`, который сбрасывал
   выбранную версию.

**Как исправлено.** Логика поиска узла вынесена в чистый helper
[`Services/PlatformVersionService.cs`](Configuration%20Management/Services/PlatformVersionService.cs)
(`FindBestNode` / `FindExactLeaf` / `MatchesCurrent` / `FilterByArchitecture`) и покрыта
юнит-тестами ([`ConfigurationManagement.Tests/PlatformVersionPickerTests.cs`](ConfigurationManagement.Tests/PlatformVersionPickerTests.cs)):

- версии БЕЗ явного суффикса показываются в обоих фильтрах (x32 и x64) — их разрядность
  неизвестна, решать должен лаунчер (#251);
- точный лист ищется по версии + разрядности;
- если выбранный узел отфильтрован, выделение осмысленно переходит на доступный узел того же
  семейства: лист той же версии → группа сборок → линия, результат диалога не теряется;
- WPF: во время перестроения дерева `SelectionChanged(null)` больше не сбрасывает выбор
  (`Views/PlatformVersionPickerWindow.xaml.cs`); Avalonia — зеркально
  (`Views/PlatformVersionPickerWindow.Avalonia.cs`).

Поведение #251 и #142 сохранено: для папки в режиме «Все» результат — чистая версия без
суффикса, при активном фильтре x64 — «8.5.1 (64)»; выбираются и листы, и папки.

**Как проверить.**

1. Установите версию **0.3.9.110** (Windows или Linux).
2. Откройте выбор версии платформы (в настройках подключения базы или при создании ИБ).
3. Выберите **8.5.1** — и лист, и папку (группу сборок).
4. Переключайте фильтр разрядности **x32 / x64 / «Все»** и сортировку **A→Z / Z→A**:
   выделение остаётся на 8.5.1; если версия полностью отфильтрована (например, у 8.5.1 только
   x32-сборка, а включён x64) — осмысленно переходит на линию 8.5, результат не пропадает.
5. Проверьте результат диалога: лист отдаёт полный вариант («8.5.1 (64)»), папка — «8.5.1 (64)»
   при фильтре x64 и «8.5.1» без суффикса в режиме «Все».

Исправлено в версии **0.3.9.297** (Windows/WPF и Linux/Avalonia).

Все четыре пункта выполнены.

**1. «Сегмент адреса» удалён из редактора.**
Поле `UrlCode` («Сегмент адреса») убрано из окна «Изменить типовую конфигурацию»
(обе платформы): адрес обновлений строится только из «НИК» конфигурации, отдельный
сегмент в логике определения не участвует. Поле «Имя конфигурации» осталось (оно
используется для сопоставления данных). Само поле в модели сохранено для
совместимости с уже созданными JSON-файлами — для новых записей не используется.

**2. «Восстановить типовые» снова заполняет НИК и табличные части.**
Раньше `BuiltInConfigTypes` заполнял ник только у БП — после восстановления в
колонке «НИК» и в редакциях у остальных конфигураций было пусто. Теперь у всех
поставляемых конфигураций заданы ники каталогов 1С: БП → `Accounting` (2.0) /
`AccountingCorp30` (3.0), ЗУП → `HRM30`, УТ → `Trade`, КА → `ARAutomation`,
Розница → `Retail`, ERP → `EnterpriseERP20`, БГУ → `StateAccounting20`; где ник
редакции отличается — задан `UrlOverride` редакции. После «Восстановить типовые»
колонки «НИК» и «Редакции» заполнены.

**3. Табличная часть редакций — 4 колонки, потеря строк устранена.**
Вместо одноколоночного списка с полями под таблицей — таблица из 4 колонок:
Имя / Ред / Подред / URL (WPF — DataGrid, Avalonia — таблица-сетка). Устранён баг,
из-за которого новая строка после сохранения и повторной правки оказывалась
пустой: инлайн-поля и их самокоммиты (перезапись значений при добавлении строки)
удалены.

**4. «Добавить» — модальный диалог.**
Вместо инлайн-кнопки с полями под таблицей появились кнопки «Добавить…»,
«Изменить…», «Удалить». «Добавить…» и «Изменить…» открывают отдельное модальное
окно `EditionEditWindow` (новая реализация для WPF и Avalonia) с полями
Имя / Ред / Подред / URL и проверкой (имя или ред непустые); «Удалить» убирает
выбранную строку.

**Тесты.** `BuiltInConfigTypesTests`: у всех встроенных конфигураций непустые
редакции, у известных — непустые ники, «восстановление → ники и редакции на
месте». `CustomConfigTypesStoreTests`: сохранение нескольких редакций с 4 полями
переживает сериализацию/десериализацию (поля и порядок на месте).

**Как проверить:**

1. Установите версию **0.3.9.297**.
2. «Типовые конфигурации» → «Изменить»: поля «Сегмент адреса» больше нет; редакции
   показаны таблицей из 4 колонок.
3. «Добавить…» — открывается модальный диалог; добавьте редакцию, сохраните,
   переоткройте — строка и её поля на месте.
4. «Восстановить типовые»: в колонках «НИК» и «Редакции» у поставляемых
   конфигураций видны данные.

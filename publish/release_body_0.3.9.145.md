# Управление конфигурациями 1С — v0.3.9.145

Серия из **девяти изменений** (0.3.9.137–0.3.9.145) по семи открытым issues автора:
регрессии выделения (#314) и выбора платформы (#304), баги локализации сравнения
конфигураций (#316) и горизонтальной прокрутки (#309), доработки сценариев (#308,
три этапа), группировка меню «Утилиты» (#318) и пожелания окна создания серверной
базы (#305). Каждое изменение реализовано на **обеих платформах**
(Windows/WPF и Linux/Avalonia).

## Изменения

1. **Shift-диапазон больше не захватывает закреплённые копии (0.3.9.137, #314)** —
   закреплённые строки (обёртки `PinnedInfobaseItem`) исключены из видимого порядка
   при построении диапазона мультивыделения: диапазон от базы A до базы B включает
   только основную копию каждой базы из её собственной группы, а клик по закреплённой
   строке как началу диапазона корректно разворачивается до реальной базы. Обычное
   Ctrl-выделение, «Для выделенных (N)…», «Найти в списке» и DnD не затронуты
   (Windows/WPF + Linux/Avalonia).

2. **Выбор «8.5.1» не перескакивает на линию 8.5 при смене разрядности (0.3.9.138,
   #304)** — дерево окна выбора версии платформы строится из полного списка
   установленных версий, а фильтр разрядности скрывает только листья: папка/лист
   «8.5.1» остаётся доступной, пока в семействе есть хотя бы один видимый вариант;
   fallback на линию выполняется лишь когда семейство полностью отфильтровано.
   Поведение суффикса разрядности (#251/#142) сохранено.

3. **«Сравнение конфигураций»: локализация — снова значения, а не ключи (0.3.9.139,
   #316)** — во всех окнах сравнения («Настройка», «Отчёт», «Прогресс») отображаются
   русские/английские тексты, а не имена ключей. Причина: блоки ключей
   `ConfigDiff.*`, `MetadataExplorer.*`, `Launcher.*`, добавленные начиная с 0.3.9.99,
   оказались вне секции `strings` JSON. Ключи перенесены обратно в `strings` в
   `ru.json`/`en.json`, добавлен недостающий `ConfigDiff.Type.Subsystem`, наборы
   ключей ru/en сверены — расхождений нет.

4. **Горизонтальная прокрутка дотягивает до последней колонки (0.3.9.140, #309)** —
   полоса снова доходит до самой правой (новой) колонки («№ релиза», «Последняя
   копия»), когда колонки не помещаются, и не появляется при помещающихся
   (анти-регресс #255). На Windows/WPF минимальная ширина контента пересчитывается
   при любом изменении видимости/ширин колонок, включая загрузку сохранённых ширин
   из настроек; на Linux/Avalonia ширина прокручиваемой области ведётся по максимуму
   из расчётной суммы колонок, вьюпорта и фактической ширины строк. Расчёт
   минимальной ширины дополнен соответствующими тестовыми сценариями.

5. **Сценарии: окно редактора по содержимому, имя базы в комбобоксе, видимое окно
   скрипта (0.3.9.141, #308)** — фиксированная высота окна редактирования сценария
   заменена на авторазмер (`SizeToContent`), внутренний скролл не появляется; на
   Linux/Avalonia комбобокс «База для примера подстановок» снова показывает имя базы
   вместо `ToString()` элемента; при снятой галке «Скрывать окно скрипта» окно
   PowerShell/cmd снова появляется (запуск через shell `UseShellExecute = true`),
   поведение по умолчанию (pre/post-команды баз, CLI) не изменилось.

6. **Сценарии: «Папка запуска» и кнопка «Изменить» (0.3.9.142, #308)** — новый
   параметр сценария `WorkingDirectory` (текстовое поле с выбором папки в редакторе,
   передаётся в `ProcessStartInfo`, превью показывает `cd "…" && …`); в окне выбора
   сценария перед запуском появилась кнопка «Изменить» — открывает редактор
   выбранного сценария и после сохранения обновляет список с восстановлением
   выделения. Старые JSON-файлы сценариев мигрируют без ошибок.

7. **Сценарии: выбор интерпретатора (0.3.9.143, #308)** — новый параметр сценария
   «Интерпретатор»: **Авто / cmd / PowerShell / sh**. Команда оборачивается
   выбранным шеллом (Windows: `cmd.exe /c`, `powershell -NoProfile -Command`;
   Linux: `/bin/sh -c`, при наличии pwsh — PowerShell). «Авто» определяет по
   платформе (прежнее поведение), старые JSON-файлы мигрируют; превью командной
   строки показывает полную строку с обёрткой. Заодно дан развёрнутый ответ на
   п.2 — все свойства базы доступны сценарию (динамическая подстановка).

8. **Меню «Утилиты» сгруппировано в подменю (0.3.9.144, #318)** — чтобы пункты не
   уходили за нижний край экрана на низких разрешениях, плоский список свернут в
   три подменю: **«Опции блокировки»**, **«Информация»** и **«Операции»**. На
   верхнем уровне остались: Командная палитра, Актуальные релизы, Монитор серверов
   1С, Консоль администрирования серверов (внешняя), Блокировка приложения и
   Проверить обновления. Хоткеи и иконки пунктов сохранены (Windows/WPF +
   Linux/Avalonia).

9. **Создание серверной базы: запоминание сервера СУБД, клик по подсказке и выбор
   сервера 1С с портом (0.3.9.145, #305)** — три доработки окна создания ИБ:
   - **Запоминание «Сервер СУБД» (+ порт)** — после успешного создания клиент-
     серверной базы значения сохраняются в настройках приложения и подставляются
     при следующем открытии окна;
   - **Кликабельная подсказка «Например localhost»** — клик подставляет пример в
     пустое поле «Сервер СУБД»;
   - **Выбор сервера 1С вместе с портом** — как в окне правки свойств базы: рядом
     с сервером появилось поле «Порт сервера 1С», выпадающий список содержит строки
     `server:port`; при выборе значение разносится на имя сервера и порт, порт
     попадает в параметры подключения и не смешивается с портом СУБД. Добавлены
     тесты форматов `server:port`.

Исправлено в версии **0.3.9.138** (Windows/WPF и Linux/Avalonia). Продолжение исправления 0.3.9.110 — устранён оставшийся «перескок» выделения.

**Что было не так.**

Сценарий: текущая версия **8.5.4** → выбираю **8.5.1** (лист или папку) → переключаю фильтр разрядности на **x64** → выделение «перескакивает» на линию **8.5**.

**Причина.**

В 0.3.9.110 fallback-логика считала переход на линию 8.5 осмысленным, но пользователь справедливо ждёт, что выбранная «8.5.1» останется доступной. Механика бага:

1. У версии 8.5.1 нет x64-сборки (например, установлена только x32).
2. `FilterByArchitecture(infos, "x64")` удаляла все её листья из списка.
3. `BuildGroupedTree` строила папки только из оставшихся версий — пустая группа «8.5.1» просто не создавалась.
4. `FindBestNode(tree, "8.5.1")` не находила папку и делала fallback на линию «8.5».

**Как исправлено.**

Дерево окна теперь строится из **полного** списка установленных версий, а фильтр разрядности применяется к листьям внутри дерева:

- [`Services/PlatformVersionService.cs`](Configuration%20Management/Services/PlatformVersionService.cs) и
  [`Services/PlatformVersionService.Linux.cs`](Configuration%20Management/Services/PlatformVersionService.Linux.cs) —
  `BuildGroupedTree(infos, archFilter)`: скрываются только листья другой разрядности; папка группы сборок («8.5.1») сохраняется, пока в её линии есть хотя бы один видимый вариант; линия целиком отфильтрованная (нет ни одного видимого листа) не показывается вовсе;
- [`Views/PlatformVersionPickerWindow.xaml.cs`](Configuration%20Management/Views/PlatformVersionPickerWindow.xaml.cs) и
  [`Views/PlatformVersionPickerWindow.Avalonia.cs`](Configuration%20Management/Views/PlatformVersionPickerWindow.Avalonia.cs) —
  `RefreshTree()` передаёт фильтр прямо в `BuildGroupedTree` вместо предварительной фильтрации списка.

Fallback на линию теперь срабатывает только когда выбранная версия действительно полностью отфильтрована (во всей линии нет ни одного видимого варианта) — в этом случае показывать нечего.

Поведение #251/#142 сохранено: лист отдаёт полный вариант («8.5.1 (64)»), папка — «8.5.1 (64)» при активном фильтре x64 и «8.5.1» без суффикса в режиме «Все»; выбираются и листы, и папки.

Покрыто новыми юнит-тестами (`ConfigurationManagement.Tests/PlatformVersionPickerTests.cs`): сценарии «8.5.4 → 8.5.1 → x64», сохранение папки при видимой линии, скрытие листьев другой разрядности, отбрасывание полностью отфильтрованной линии. Все 610 тестов проходят; `dotnet build -p:BuildLinux=true` — без ошибок.

**Как проверить.**

1. Установите версию **0.3.9.138** (Windows или Linux).
2. Откройте выбор версии платформы (в настройках подключения базы или при создании ИБ).
3. Выберите **8.5.1** — и лист, и папку (группу сборок).
4. Переключите фильтр разрядности на **x64**: выделение остаётся на 8.5.1 (у версии без x64-сборки — на папке 8.5.1), на линию 8.5 не уходит.
5. Проверьте результат диалога: лист — полный вариант, папка при x64 — «8.5.1 (64)», в режиме «Все» — «8.5.1».

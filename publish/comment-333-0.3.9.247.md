Реализовано в версии **0.3.9.247** (Windows/WPF и Linux/Avalonia).

**Новый справочник «Учетные данные ИТС»** вместо двух полей логин/пароль в настройках:

- Окно открывается из подменю **«Утилиты → Информация»** и из настроек (кнопка «Открыть справочник»).
  Список записей: наименование, логин, флажок **«Основная»** (только для чтения) и кнопки
  **«Добавить»**, **«Изменить»**, **«Удалить»**, **«Задать основным»**. Редактор — модальное окно
  со скинингом по теме приложения, фокус по умолчанию на первом поле («Наименование»).
- **Правила «Основная»** (по вашему комментарию):
  1. флажок «Основная» в списке отображается только для чтения;
  2. смена основной — ТОЛЬКО кнопкой «Задать основным» (две основные из UI поставить нельзя);
  3. при загрузке файла: если основных 2+ — основной остаётся первый найденный; если 0 —
     основной становится первая запись;
  4. при удалении записи с пометкой «Основная» основной становится первая запись списка.
- Хранилище — отдельный читаемый JSON-файл **`its_accounts.json`** рядом с настройками
  (атомарная запись, UTF-8 без `\uXXXX`), по образцу `custom_config_types.json`. Файл можно
  править вручную и переносить между установками.
- **Миграция**: при первом запуске после обновления текущие логин/пароль ИТС из старых
  настроек (`UpdatesLogin`/`UpdatesPassword`) автоматически переносятся в запись «Основная».
  Перенос идемпотентный — повторный запуск дублей не создаёт; старые поля в настройках не
  удаляются (обратная совместимость со старыми версиями).
- **Настройки**: вместо двух полей — выбор элемента справочника (ComboBox; первый пункт —
  «Основная») + кнопка открытия справочника.
- **Использование**: авторизация при запросах к сайту 1С (`OneCUpdatesService`, HTTP Basic Auth
  и вход login.1c.ru) использует выбранную в настройках учётную запись или «Основную».
- **Типовые конфигурации** (#321): у каждой записи типовой конфигурации добавлено поле
  **«Учётная запись»** (опционально; если не указана — используется «Основная»). Модель
  `OneCConfigType` дополнена полем `AccountId`; обратная совместимость: отсутствие поля в
  старых JSON-файлах = пусто (основная).
- Пароль маскируется при сохранении в лог (`SensitiveDataMasker`) и не попадает в журнал.

**Тесты**: юнит-тесты хранилища — миграция (первый запуск, повторный запуск без дублей,
сохранение старых настроек), правила «Основная» (2+ → первый найденный, 0 → первая запись,
удаление основной → первая), CRUD (добавление/правка/удаление/смена основной), резолв
учётной записи для типовой конфигурации (пусто → основная, явный выбор, отсутствующая
запись → основная), маскирование пароля в логе, читаемость UTF-8 и устойчивость к битому
файлу. Полный прогон зелёный, регрессия `CustomConfigTypesStoreTests` без изменений.

**Как проверить.**

1. Установите версию **0.3.9.247** (Windows или Linux).
2. Откройте «Утилиты → Информация → Учетные данные ИТС»: пустой справочник (если логин в
   старых настройках не был задан) либо запись «Основная», созданная миграцией из настроек.
3. «Добавить» → заполните наименование, логин и пароль → «Сохранить». Если это первая запись —
   она становится основной. Добавьте вторую запись: основная не меняется автоматически.
4. «Задать основным» у второй записи — флажок «Основная» переходит на неё (единственная
   основная). Попробуйте поменять флажок вручную — он не редактируется.
5. Удалите основную запись — основной становится первая запись списка.
6. В настройках вместо полей «Логин/Пароль» теперь выпадающий список учётных записей
   («Основная» или конкретная) и кнопка «Открыть справочник».
7. Проверьте файл `its_accounts.json` рядом с настройками: читаемый, кириллица не экранирована.
8. В окне «Типовые конфигурации» появилась колонка «Учётная запись»; в редакторе — поле выбора
   (пусто = «Основная»).

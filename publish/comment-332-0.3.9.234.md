Исправлено в версии **0.3.9.234** (Windows/WPF и Linux/Avalonia).

**Что было сломано.** Ссылка на веб-базу с завершающим сегментом локали, например
`https://accounting.demo.1c.ru/accounting/ru_RU/`, при «Перейти по ссылке» открывалась не как
веб-база, а как страница локали: весь URL передавался браузеру без изменений, и вместо базы
открывался раздел `ru_RU` публикации 1С.

**Причина.** В ветке http/https функций `ParseLink` (Windows) и `LaunchByLink` (Linux) URL
возвращался как есть (`WebUrl = value` / `OpenUrl(value)`) без нормализации пути — сегмент
локали, который является чисто сервисной частью URL публикации 1С, считался частью адреса базы.

**Как исправлено.**

- Добавлен чистый статический метод `StripWebLocaleSegment` (общий файл
  `OneCLauncher.Arguments.Shared.cs`, обе платформы): отбрасывает завершающий сегмент локали
  вида `/ru_RU/`, `/en_US` из пути web-ссылки.
- Регулярное выражение `/([a-z]{2,3})_[A-Z]{2}` применяется **только к конечному сегменту
  пути** (часть до `?`/`#`): сегмент вида `ru_RU` в середине пути, query/fragment и
  trailing-slash без локали не затрагиваются; завершающий слеш сохраняется —
  результат для примера: `https://accounting.demo.1c.ru/accounting/`.
- Нормализация подключена только в ветке http/https (ссылки `e1c://…` не изменяются).
- Юнит-тесты `WebLinkLocaleTests`: позитив `ru_RU`/`en_US` (со слешем и без, с query после
  локали); негатив — локаль в середине пути, отсутствие локали, локаль только в
  query/fragment, trailing-slash, регистрозависимость шаблона, null/пустая строка.

**Как проверить.**

1. Установите версию **0.3.9.234** (Windows или Linux).
2. Выберите базу → «Перейти по ссылке…» (или вставьте ссылку в поле «Открыть базу по ссылке»)
   и укажите `https://accounting.demo.1c.ru/accounting/ru_RU/`.
3. В браузере должна открыться веб-база (`/accounting/`), а не страница локали `ru_RU`.
4. Проверьте, что обычные ссылки (без локали, с query, с сегментом `ru_RU` в середине пути)
   открываются как раньше.

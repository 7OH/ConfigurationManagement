Исправлено в версии **0.3.9.302**.

**Что было.**

1. «Откуда взялся порт» в предупреждении «версия отличается»: у клиент-серверных баз порт хранится в отдельном поле `ConnectionSettings.Port` со значением по умолчанию **1541**, даже если пользователь порт нигде не вводил. Сравнение серверов ([`SameServer`](Configuration%20Management/Services/CreateInfobaseService.cs)) разбирало порт только из строки сервера и игнорировало поле `conn.Port` — для типичного хранения («localhost» + `Port=1541`) обе стороны давали порт 0, базы на `localhost:1541` и `localhost:1545` считались одним сервером, а в предупреждение попадал адрес «первой попавшейся» базы из списка — случайный с точки зрения пользователя.
2. «Сервер СУБД» сохранялся только после успешного создания базы (`SaveLastDbServer` вызывался внутри `TryCreate`): если ввести сервер и закрыть окно без создания (или создание упало) — ввод терялся.

**Что сделано.**

1. [`Services/CreateInfobaseService.cs`](Configuration%20Management/Services/CreateInfobaseService.cs): сравнение серверов теперь учитывает эффективный порт из отдельного поля `ConnectionSettings.Port` (если у обеих сторон порт задан явно и отличается — серверы разные; если порт не задан хотя бы у одной стороны — fallback «равны»). Адрес найденной базы строится новым нормализатором `BuildBaseServerAddress` без задвоения порта (порт может храниться и в строке сервера, и в поле).
2. Текст предупреждения показывает **оба адреса**: введённый пользователем сервер и адрес базы из списка, поясняя, что порт взят из списка баз приложения. Локализация обновлена в ru/en.
3. [`Views/CreateInfobaseWindow.xaml.cs`](Configuration%20Management/Views/CreateInfobaseWindow.xaml.cs) и [`CreateInfobaseWindow.Avalonia.cs`](Configuration%20Management/Views/CreateInfobaseWindow.Avalonia.cs): `SaveLastDbServer` вынесен в `ICreateInfobaseService` и вызывается также при закрытии окна — ввод «Сервера СУБД» (и порта) сохраняется, даже если база не была создана; пустые значения не перетирают предыдущие.

**Тесты** ([`CreateInfobaseDbServerStringTests.cs`](ConfigurationManagement.Tests/CreateInfobaseDbServerStringTests.cs)): добавлены 9 тестов — явные порты равные/разные/fallback, нормализация адреса без задвоения порта (включая дефолт 1541), сохранение «Сервера СУБД» в настройки для следующего открытия.

**Как проверить:** обновитесь до **0.3.9.302**; введите сервер `localhost:1541`, а в списке баз клиент-серверные базы на порту 1545 — предупреждение о различии версий НЕ появится (серверы разные). При совпадении сервера предупреждение покажет оба адреса и объяснит источник порта. Введите «Сервер СУБД» и закройте окно без создания — при следующем открытии поле подставлено; после успешного создания значение по-прежнему сохраняется.

Часть 2 из 2, исправлено в версии **0.3.9.284** (Windows/WPF и Linux/Avalonia).

**Что было:** «добавляешь строку в таблицу релизов — вроде видно в списке — после ОК — в списке одну строку показывает релизов, после открытия на правку ещё раз — тоже одна строка в табличной части. Где-то ошибка при сохранении».

**Причина.** Значения полей редакции (Имя, Редакция, Подредакция, Сегмент адреса) переносились в модель только в момент смены выделения строки или по кнопке ОК (`CommitEditionFields`). Если выделение в таблице слетало (например, при клике в поле или перестроении списка) — введённый текст в поля так и не попадал в модель, и при сохранении редакция оставалась пустой.

**Как исправлено:**

1. **Автосохранение полей при вводе.** В редакторе конфигурации ([`ConfigTypeEditWindow.xaml.cs`](Configuration%20Management/Views/ConfigTypeEditWindow.xaml.cs), зеркало [`ConfigTypeEditWindow.Avalonia.cs`](Configuration%20Management/Views/ConfigTypeEditWindow.Avalonia.cs)) добавлены обработчики `TextChanged` на поля «Имя», «Редакция», «Подредакция» и «Сегмент адреса»: значение теперь фиксируется в текущей редакции немедленно, а не по смене выделения. Потеря ввода при слетевшем выделении исключена.

2. **Очистка полей при добавлении строки.** При нажатии «Добавить» новая строка создаётся с пустыми полями (`ClearEditionFields`) — ранее в полях мог оставаться текст от предыдущей редакции, который при автосохранении перезаписал бы только что добавленную строку.

3. **Сохранение всей табличной части.** Список редакций целиком переносится в модель при нажатии ОК (без частичного копирования), поэтому все добавленные строки релизов доходят до JSON-хранилища.

**Тесты.** Добавлен регрессионный тест `SaveLoad_MultipleEditions_ArePreserved` в [`CustomConfigTypesStoreTests.cs`](ConfigurationManagement.Tests/CustomConfigTypesStoreTests.cs): две редакции с подредакциями и сегментами адреса → сохранение → повторная загрузка → количество строк и значения сохранены. Полный набор `dotnet test` зелёный (1580), кросс-сборка Linux (`dotnet build -p:BuildLinux=true`) без ошибок.

**Как проверить:**

1. Установите **0.3.9.284** ([релиз v0.3.9.284](https://github.com/sivatorov/ConfigurationManagement/releases/tag/v0.3.9.284)).
2. Откройте «Типовые конфигурации» → правка конфигурации → «Добавить» строку в таблицу релизов, заполните поля (не только Имя, но и Редакцию/Подредакцию).
3. Нажмите ОК, затем снова откройте конфигурацию на правку — все добавленные строки релизов на месте.

Исправлено в версии **0.3.9.159** (Windows/WPF и Linux/Avalonia).

**Что было сломано.** Окно «Связать с конфигурацией» (правый клик по базе) имело четыре
проблемы:

1. **«Выбор версии не работает, когда конфигурация выбрана автоматом правильно; если
   выбирать другие — даёт выбрать версию»** — при открытии окна с уже определённой связью
   (например «Бухгалтерия предприятия», редакции «3.0»/«2.0») список редакций оставался
   пустым, поэтому выбрать редакцию было невозможно. При ручной смене конфигурации список
   редакций заполнялся — отсюда и разница в поведении.
2. **«Данное окно не является модальным»** — на Windows/WPF `ShowDialog()` вызывался без
   владельца (`Owner`): окно не блокировало главное и могло уходить под него.
3. **«ГДЕ вводить и исправлять ключевые кусочки адреса, которые идут после releases?
   Например AccountingCorp нигде не фигурирует»** — ник конфигурации (сегмент
   `https://releases.1c.ru/project/<ник>`) нигде не показывался и не правился.
4. **«Я думал связь идёт через информацию о конфигурации… прописал в базе — и связь
   работает»** — кнопка «Определить версию» читала имя/версию базы, но никак не связывала
   её с типовой конфигурацией: приходилось выбирать конфигурацию вручную.

**Причины.**

1. Обработчик смены конфигурации подавлялся флагом инициализации окна, а отдельного
   вызова «заполнить редакции» при старте не было — редакции не заполнялись только в
   случае автоопределённой конфигурации. В Linux/Avalonia вдобавок терялись начальные
   значения окна (выбор конфигурации, режим URL, ручная ссылка): они устанавливались до
   построения дерева UI и перезатирались при его создании.
2. Отсутствовал `win.Owner = Application.Current.MainWindow`.
3. Сегмент (ник) хранился только в карточке типовой конфигурации и в окне связи не
   отображался вовсе.
4. Результат `ReadAndApply` игнорировался — сопоставления с типовыми конфигурациями не
   выполнялось.

**Как исправлено.**

- Список редакций теперь заполняется и при открытии окна, и при смене конфигурации
  (`ApplyConfigSelection`); выбор редакции всегда пересобирает адрес каталога релизов.
- Окно открывается модально с владельцем (`win.Owner = MainWindow` + отложенный показ
  через `DispatcherPriority.Input`, как у «Актуальных релизов» и «Типовых конфигураций»).
  На Linux/Avalonia окно уже было модальным (`ModalWindowBase.ShowDialogSync`) —
  подтверждено и сохранено; дополнительно исправлена потеря начальных значений при
  построении UI.
- В окне добавлено поле **«Сегмент адреса (ник)»**: в нём виден действующий сегмент
  (персональный сегмент базы либо ник типовой конфигурации), его можно отредактировать —
  значение сохраняется в базе и сразу пересобирает адрес. Рядом — подсказка, что этот
  сегмент хранится в типовой конфигурации, и кнопка **«Список типовых конфигураций»**,
  открывающая соответствующее окно.
- Кнопка **«Определить версию»** теперь автоматически сопоставляет прочитанное имя
  конфигурации базы со списком типовых (встроенные + пользовательские): при совпадении
  подставляется конфигурация, редакция (по префиксу версии, например «3.0.142.32» →
  «3.0») и пересобирается адрес — «прописал в базе — и связь работает». Если имя не
  найдено — выбор не меняется, выводится понятное сообщение.
- При проверке обновлений (F9) персональный сегмент базы подставляется в адрес вместо
  ника конфигурации. Сохранение `UpdateConfigCode`/`UpdateUrlOverride` не изменено;
  новое поле `UpdateUrlSegment` необязательное и обратно совместимо со старыми файлами баз.

**Где вводить и исправлять «кусочки адреса после releases».**

- Откройте окно «Связать с конфигурацией» (правый клик по базе). В поле **«Сегмент
  адреса (ник)»** показан действующий сегмент — часть адреса после
  `https://releases.1c.ru/project/`, например `AccountingCorp30`. Введите нужное значение
  и нажмите «Сохранить» — оно сохранится за этой базой, адрес пересоберётся сразу.
- Если оставить поле равным нику типовой конфигурации, оно не «закрепляется» за базой:
  адрес продолжит браться из карточки конфигурации (окно «Список типовых
  конфигураций» — там сегмент задаётся по умолчанию для всех баз, связанных с этой
  конфигурацией).

**Как проверить.**

1. Установите версию **0.3.9.159** (Windows или Linux).
2. Правый клик по базе → «Связать с конфигурацией»: окно открывается модально, в списке
   редакций уже выбрана редакция по умолчанию, адрес каталога релизов сформирован.
3. Смените конфигурацию — редакции обновляются, адрес пересобирается. Выберите другую
   редакцию — адрес меняется.
4. Нажмите «Определить версию»: для базы с известным именем конфигурации (например
   «Бухгалтерия предприятия») связь подставится автоматически, в том числе редакция по
   версии базы.
5. Проверьте поле «Сегмент адреса (ник)»: введите заведомо неверный ник, нажмите
   «Сохранить», затем F9 — в окне проверки будет виден адрес с вашим сегментом.
   Верните правильное значение (или сотрите поле, чтобы снова наследовать ник
   конфигурации) и сохраните.

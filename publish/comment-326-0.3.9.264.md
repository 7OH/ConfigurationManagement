Исправлено в версии **0.3.9.264** (Windows/WPF и Linux/Avalonia). Продолжение фикса 0.3.9.238 — теперь по вашему сценарию: выделение с Ctrl/Shift больше не «уходит» из закреплений в общий список.

**Что было не так.**

1. Shift-клик от одной закреплённой базы до другой выделял диапазон по ОБЩЕМУ списку — «полсписка обычного», а не строки между ними в закреплениях.
2. Ctrl/Shift-выбор закреплённой базы визуально подсвечивал её копию в общем списке, а не саму закреплённую строку — казалось, что выделение происходит «не в закреплении, а в общем списке».

**Причина.**

- Порядок строк секции «Закреплённые» для Shift-диапазона строился по контейнерам дерева. На Avalonia строка узла «Закреплённые» несёт обёртку `PinnedInfobaseItem`, и проверка «это обычная база» пропускала все такие строки — порядок оставался ПУСТЫМ. При пустом порядке код подменял его списком всех баз — отсюда «полсписка обычного» на Linux (та же подмена могла сработать на Windows, когда контейнеры закреплённых строк не были реализованы виртуализацией — например, после прокрутки списка).
- Пакетная подсветка намеренно не вешалась на закреплённые строки (прежний фикс «лишнего выделения»), поэтому любой батч-выбор в закреплениях «светил» обычную копию базы.

**Как исправлено.**

1. Порядок секции «Закреплённые» теперь строится по ДАННЫМ узла, а не по контейнерам — новый чистый метод [`BatchSelectionHelper.BuildPinnedSectionOrder`](Configuration%20Management/Services/BatchSelectionHelper.cs) (и общая точка разворачивания обёртки `Unwrap`). Порядок не зависит от виртуализации и всегда совпадает с экраном.
2. [`SelectRange`](Configuration%20Management/ViewModels/MainViewModel.Batch.cs) больше НИКОГДА не подменяет пустой порядок закреплений общим списком: при отсутствии порядка Shift выбирает только строку под кликом, как при отсутствии якоря. Правило секций (#326) не нарушается ни при каких условиях.
3. Подсветка строк стала зависеть от секции набора — новое свойство [`MainViewModel.BatchSelectionSectionIsPinned`](Configuration%20Management/ViewModels/MainViewModel.Batch.cs): обычные строки светятся только когда набор собран в обычном списке, закреплённые — только когда набор собран в «Закреплённых». Копии выбранных баз в другой секции при этом не подсвечиваются.

Файлы:

- [`Services/BatchSelectionHelper.cs`](Configuration%20Management/Services/BatchSelectionHelper.cs) — `BuildPinnedSectionOrder` + `Unwrap` (чистая логика, покрыта тестами);
- [`ViewModels/MainViewModel.Batch.cs`](Configuration%20Management/ViewModels/MainViewModel.Batch.cs) — признак секции набора, порядок закреплений из модели, фикс подмены в `SelectRange`;
- WPF [`Views/MainWindow.Tree.cs`](Configuration%20Management/Views/MainWindow.Tree.cs) и [`Views/MainWindow.xaml`](Configuration%20Management/Views/MainWindow.xaml) — порядок из модели + два триггера подсветки (обычная/закреплённая строка по секции набора);
- Avalonia [`Controls/LeveledTreeView.Avalonia.cs`](Configuration%20Management/Controls/LeveledTreeView.Avalonia.cs) и [`Views/MainWindow.Avalonia.Tree.cs`](Configuration%20Management/Views/MainWindow.Avalonia.Tree.cs) — порядок из модели + подсветка по секции набора.

**Тесты.**

[`BatchSelectionHelperTests`](ConfigurationManagement.Tests/BatchSelectionHelperTests.cs): Shift-диапазон в закреплениях при более длинном обычном списке (обычные строки в набор не попадают); порядок закреплённой секции по данным узла (обёртки `PinnedInfobaseItem`, дедупликация); пустой порядок закреплений → Shift выбирает только цель; Ctrl-клики внутри закреплений не трогают обычный список; разворачивание `Unwrap`. Полный набор `dotnet test` зелёный (1495), кросс-сборка Linux (`dotnet build -p:BuildLinux=true`) без ошибок.

**Как проверить в 0.3.9.264.**

1. Закрепите 3–5 баз, чтобы узел «Закреплённые» был заметно короче обычного списка.
2. Обычный клик по первой закреплённой строке, затем Shift+клик по последней закреплённой — выделяются ТОЛЬКО закреплённые строки между ними (обычный список не затрагивается).
3. Ctrl+клик по закреплённой строке — подсвечивается сама закреплённая строка, а не её копия в общем списке.
4. Прокрутите обычный список вниз и повторите Shift-выбор внутри закреплений (после прокрутки назад) — диапазон по-прежнему строится по закреплённым.
5. Повторите на Linux (Avalonia).

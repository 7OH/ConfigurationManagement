Исправлено в версии **0.3.9.316** (Windows/WPF и Linux/Avalonia; issue #348 «Вставка адреса хранилища»).

**Что было.**

Кнопка «Вставить» на вкладке «Хранилище» правки свойств базы разбирала единое поле подключения к хранилищу, скопированное из 1С, и **теряла протокол**: при вставке `tcp://dev:555/base` поле «Сервер» заполнялось как `dev:555`, хотя подсказка поля и модель (`RepositorySettings.Server`) предполагают адрес **с протоколом** — `tcp://dev:555`.

**Что сделано.**

1. **Схема сохраняется в адресе сервера.** Метод разделения единого поля подключения в
   [`ConnectionSettingsViewModel.cs`](https://github.com/sivatorov/ConfigurationManagement/blob/main/Configuration%20Management/ViewModels/ConnectionSettingsViewModel.cs)
   больше не отбрасывает префикс до `://`: сервер = `<схема>://<host[:port]>`, имя хранилища — без схемы. Примеры:
   - `tcp://dev:555/base` → сервер **`tcp://dev:555`**, имя хранилища **`base`**;
   - `file:///home/user/store` → сервер `file:///home/user`, имя хранилища `store`;
   - `http(s)://host/store` → сервер с сохранённой схемой.
   Поведение без схемы (просто `dev:555/base`) не изменилось.
2. **Сборка пути запуска 1С согласована** — путь `tcp://сервер:порт/имяХранилища` собирается из `Repository.Server + RepositoryName`, поэтому сохранение схемы в `Server` не даёт двойного `tcp://` (проверены потребители — сборка командной строки запуска, импорт старт-менеджера).
3. **Avalonia/Linux покрыта автоматически** — разбор выполняется в общем ViewModel, окно WPF и его Avalonia-зеркало используют один код.

**Как проверить.**

1. Установите **0.3.9.316** (Windows или Linux).
2. Откройте свойства базы → вкладка **«Хранилище»** → кнопка **«Вставить»**.
3. Вставьте `tcp://dev:555/base`: поле **«Сервер»** должно заполниться значением **`tcp://dev:555`** (с протоколом, как в подсказке поля), **«Имя хранилища»** — `base`.
4. Проверьте варианты с `file://` и `http(s)://` — протокол сохраняется в поле «Сервер», имя хранилища — без схемы.
5. Проверьте запуск базы из этого хранилища: командная строка 1С собирается без двойного `tcp://`.

**Тесты.** +7 новых сценариев в [`ConnectionSettingsViewModelTests.cs`](https://github.com/sivatorov/ConfigurationManagement/blob/main/ConfigurationManagement.Tests/ConnectionSettingsViewModelTests.cs): разбор с `tcp://`, `file://`, `http(s)://`, без схемы — сервер со схемой и корректное имя хранилища; регресс существующих сценариев разбора (issue #140).

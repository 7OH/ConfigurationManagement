## РћРїРёСЃР°РЅРёРµ

В стандартном загрузчике 1С ссылка на демонстрационную базу вида https://accounting.demo.1c.ru/accounting/ru_RU/ обрабатывается при добавлении информационной базы с отбрасыванием сегмента локали ru_RU — то есть адрес приводится к виду https://accounting.demo.1c.ru/accounting/. Из-за этого база открывается как обычная веб-база, а не как веб-страница конкретной локали.

## Что делает ConfigurationManagement сейчас
Команда «Перейти по ссылке» (MainViewModel.OpenInfobaseByLink, Services/OneCLauncher.Arguments.cs, LaunchByLink/ParseLink) разбирает только такие форматы:
- e1c://… — передаётся стандартному загрузчику 1С;
- файловая база — путь к каталогу;
- клиент-серверная — server\База или Srvr="…";Ref="…";
- веб-база — http://… или https://…, и такая ссылка открывается в браузере по умолчанию.
Никакой обработки сегмента локали нет: поиск по ru_RU, 1cfresh, demo.1c.ru в исходниках ничего не находит. Значит ссылка с …/ru_RU/ уходит в браузер как есть, и результат отличается от поведения стандартного загрузчика.

## РљРѕРјРјРµРЅС‚Р°СЂРёР№ 1 РѕС‚ sivatorov (2026-10-01T10:40:06Z)

Исправлено в версии **0.3.9.234** (Windows/WPF и Linux/Avalonia).

**Что было сломано.** Ссылка на веб-базу с завершающим сегментом локали, например
`https://accounting.demo.1c.ru/accounting/ru_RU/`, при «Перейти по ссылке» открывалась не как
веб-база, а как страница локали: весь URL передавался браузеру без изменений, и вместо базы
открывался раздел `ru_RU` публикации 1С.

**Причина.** В ветке http/https функций `ParseLink` (Windows) и `LaunchByLink` (Linux) URL
возвращался как есть (`WebUrl = value` / `OpenUrl(value)`) без нормализации пути — сегмент
локали, который является чисто сервисной частью URL публикации 1С, считался частью адреса базы.

**Как исправлено.**

- Добавлен чистый статический метод `StripWebLocaleSegment` (общий файл
  `OneCLauncher.Arguments.Shared.cs`, обе платформы): отбрасывает завершающий сегмент локали
  вида `/ru_RU/`, `/en_US` из пути web-ссылки.
- Регулярное выражение `/([a-z]{2,3})_[A-Z]{2}` применяется **только к конечному сегменту
  пути** (часть до `?`/`#`): сегмент вида `ru_RU` в середине пути, query/fragment и
  trailing-slash без локали не затрагиваются; завершающий слеш сохраняется —
  результат для примера: `https://accounting.demo.1c.ru/accounting/`.
- Нормализация подключена только в ветке http/https (ссылки `e1c://…` не изменяются).
- Юнит-тесты `WebLinkLocaleTests`: позитив `ru_RU`/`en_US` (со слешем и без, с query после
  локали); негатив — локаль в середине пути, отсутствие локали, локаль только в
  query/fragment, trailing-slash, регистрозависимость шаблона, null/пустая строка.

**Как проверить.**

1. Установите версию **0.3.9.234** (Windows или Linux).
2. Выберите базу → «Перейти по ссылке…» (или вставьте ссылку в поле «Открыть базу по ссылке»)
   и укажите `https://accounting.demo.1c.ru/accounting/ru_RU/`.
3. В браузере должна открыться веб-база (`/accounting/`), а не страница локали `ru_RU`.
4. Проверьте, что обычные ссылки (без локали, с query, с сегментом `ru_RU` в середине пути)
   открываются как раньше.

Версия **0.3.9.234**: [CHANGELOG](https://github.com/sivatorov/ConfigurationManagement/blob/main/CHANGELOG.md).

## РљРѕРјРјРµРЅС‚Р°СЂРёР№ 2 РѕС‚ Ollivhv (2026-10-02T08:10:09Z)

**Уточнение: задача была про добавление базы в список, а не про переход по ссылке**

Похоже, сделан только один сценарий — «Перейти по ссылке». Исходная формулировка задачи и скриншот были
про другое: стандартный загрузчик 1С при **добавлении** базы по ссылке сам предлагает убрать сегмент локали
и в случае согласия пользователя сохраняет в список адрес уже без `ru_RU`. В ConfigurationManagement этого
нет ни в тихом виде, ни с подтверждением: ссылка сохраняется как есть, вместе с сегментом локали.

**Что ожидается (как в стандартном загрузчике)**

1. Пользователь добавляет базу и вводит/вставляет `https://accounting.demo.1c.ru/accounting/ru_RU/`
   (в поле «URL публикации» или через диалог вставки ссылки).
2. Приложение либо обрезает завершающий сегмент локали, либо (как это делает 1CEStart) спрашивает
   подтверждение — вместо этого адрес остаётся с `ru_RU`.
3. В списке баз сохраняется `https://accounting.demo.1c.ru/accounting/`.

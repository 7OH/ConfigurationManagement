Исправлено в версии **0.3.9.281** (Windows/WPF и Linux/Avalonia).

**Что было.**

«В терминале `rac.exe host:port cluster list` работает и показывает кластер, а монитор вывод не распознаёт». У парсера таблиц rac было два ограничения:

- строки делились по табуляции либо fallback «2+ пробела подряд» — последний **резал имена с несколькими пробелами** (например «Тест  кластер» превращался в два поля);
- stdout/stderr читались строго как UTF-8, тогда как rac на Windows пишет в OEM-кодовой странице консоли (обычно cp866) — кириллица в выводе приходила в виде мусора.

**Как исправлено.**

1. [`Services/RacOutputParser.cs`](Configuration%20Management/Services/RacOutputParser.cs): `ParseTable` теперь умеет позиционный разбор по границам колонок из строки заголовка. Он применяется только при единообразном выравнивании (границы заголовка подтверждаются строками данных), поэтому внутренние пробелы значения (имя кластера, строка подключения) больше не теряются, а неравномерно выровненный вывод по-прежнему обрабатывается прежним fallback.
2. [`Services/RacClient.cs`](Configuration%20Management/Services/RacClient.cs): вывод читается сырыми байтами и декодируется автоматически: строгий UTF-8 (Linux/Avalonia); если байты невалидны как UTF-8 — cp866 (OEM Windows) с резервом cp1251. Зарегистрирован `CodePagesEncodingProvider`, чтобы кодовые страницы были доступны и в кросс-платформенных сборках.

**Тесты.**

Добавлены кейсы в [`RacOutputParserTests`](ConfigurationManagement.Tests/RacOutputParserTests.cs) (позиционный разбор: двойные пробелы внутри имени, короткие значения, CRLF, смешанный заголовок с табами) и [`RacClientTests`](ConfigurationManagement.Tests/RacClientTests.cs) (`DecodeRacOutput`: UTF-8 / cp866 / однобайтовый fallback без потерь). Полный набор `dotnet test` зелёный (1561), кросс-сборка Linux (`dotnet build -p:BuildLinux=true`) без ошибок.

**Как проверить:**

1. Установите **0.3.9.281** ([релиз v0.3.9.281](https://github.com/sivatorov/ConfigurationManagement/releases/tag/v0.3.9.281)).
2. Откройте монитор «Серверы 1С», подключитесь к кластеру (`host:port` агента ragent 1540 или RAS 1545) — список кластеров/процессов/сеансов должен заполниться.

Если проблема сохранится на вашем стенде — пришлите, пожалуйста, фрагмент журнала приложения с командами `RAC:` (они уже пишут путь к найденному rac и полную команду без пароля) — по нему сравню фактический формат вывода с разбором.

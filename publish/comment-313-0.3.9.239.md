Исправлено в версии **0.3.9.239** (Windows/WPF и Linux/Avalonia). Продолжение фикса 0.3.9.114.

**Что было не так.**

После исправления 0.3.9.114 остался сценарий:

1. Первую строку делаем просто текущей (обычный клик, БЕЗ Ctrl).
2. Дальше Ctrl-кликами добавляем другие базы.
3. Правый клик по последней Ctrl-строке — из набора «Для выделенных» пропадает та
   самая первая строка, которая была текущей (блок «Для выделенных (N)…» показывает
   меньше баз, чем ожидалось).

Если первую строку сразу пометить Ctrl, правый клик её не терял — отличие как раз
в «просто текущей» строке.

**Причина.**

Состояния «текущая строка» (курсор без выделения в наборе) и «строка из
мультивыделения» не различались явно: правый клик проходил через общий путь
обработки кликов, где модификаторы могли повлиять на набор. Строка, которая была
«просто текущей», не входила в набор, но путь обработки правого клика мог её
затрагивать (и, по ощущению, «терял» при открытии меню).

**Как исправлено.**

Правый клик теперь обрабатывается отдельной веткой и меняет ТОЛЬКО основное
выделение под курсором (`IsSelected`/`SelectedInfobase`); набор «для выделенных»
при этом не трогается вообще:

- **Linux/Avalonia** —
  [`LeveledTreeView.Avalonia.cs`](Configuration%20Management/Controls/LeveledTreeView.Avalonia.cs),
  `OnRowPointerPressed`: правая кнопка — ранний выход (только `SelectRow` +
  `e.Handled`) ДО всех веток модификаторов. Любые будущие правки веток Ctrl/Shift
  не смогут задеть правый клик.
- **Windows/WPF** —
  [`OnInfobaseTree_PreviewMouseRightButtonDown`](Configuration%20Management/Views/MainWindow.Events.cs):
  правило зафиксировано явно — ни `ToggleBatchSelection`, ни `SelectRange`, ни
  `ClearBatchSelection`; модификаторы при правом клике игнорируются.
- Чистый хелпер
  [`BatchSelectionHelper.BuildRightClickSet`](Configuration%20Management/Services/BatchSelectionHelper.cs)
  фиксирует семантику построения набора при правом клике: набор строится по
  фактически выделенным строкам, «бывшая текущая» (без Ctrl) в него не добавляется,
  toggle не выполняется.

Строка входит в набор «Для выделенных» только после Ctrl/Shift-клика по ней —
это поведение не изменилось и теперь закреплено тестами.

**Как проверить.**

1. Обычный клик по первой базе (без Ctrl) — она просто текущая.
2. Ctrl+клики по 2–3 другим базам — они помечаются вторичным фоном.
3. Правый клик по последней Ctrl-строке — блок «Для выделенных (N)…» показывает
   ровно базы, отмеченные Ctrl (первые не теряются, «текущая» не добавляется).
4. Если первую строку пометить сразу Ctrl — после правого клика она тоже остаётся.
5. Shift-диапазон и обычный клик (сброс набора) не изменились.

[`BatchSelectionHelperTests`](ConfigurationManagement.Tests/BatchSelectionHelperTests.cs));
`dotnet build -p:BuildLinux=true` — без ошибок.

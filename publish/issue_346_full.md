## РљРѕРјРјРµРЅС‚Р°СЂРёР№ 1 РѕС‚ sivatorov (2026-10-05T12:56:54Z)

Исправлено в версии **0.3.9.309**.

**Как устроен поиск (алгоритм сопоставления).**

Проверка обновлений (F9) работает в два уровня:

1. **Явная привязка** — если для базы задана связь («Связать с конфигурацией»), типовая
   конфигурация ищется по коду связи. Явная привязка имеет приоритет.
2. **Автоопределение без привязки** — по имени конфигурации базы (вкладка «Платформа»,
   поля «Конфигурация»/«№ релиза»). Имя сравнивается со списком типовых по признакам в
   порядке приоритета: точное наименование → точное внутреннее имя конфигурации 1С
   (`ConfigName`) → сегмент адреса обновлений → вхождение имени (выбирается самое длинное
   совпавшее, чтобы ЗУП не «перекрывалась» Бухгалтерией). При совпадении строится адрес
   каталога `releases.1c.ru/project/<ник>` и проверяется последняя версия.

**Почему возникало «База не связана с типовой».**

Имя конфигурации базы приходит из метаданных 1С и хранится **без пробелов** —
«ЗарплатаИУправлениеПерсоналом», а наименование типовой записи — с пробелами:
«Зарплата и управление персоналом». В записи типовой есть отдельное поле внутреннего
имени `ConfigName = ЗарплатаИУправлениеПерсоналом` (для Бухгалтерии — `БухгалтерияПредприятия`
и т.д.), которое как раз совпадает с именем базы 1:1, но до 0.3.9.309 оно в автоопределении
НЕ использовалось — поэтому сопоставление не находилось и выводилось «База не связана».
Теперь точное совпадение по внутреннему имени (`ConfigName`) добавлено вторым признаком.

**Про редакции («3.1» vs «3» и «1»).**

Разделять на «Ред = 3» и «Подред = 1» не нужно. Сегмент `Ред` хранится строкой и может
содержать «3.1» или «3.0» целиком; сопоставление с версией базы выполняется по префиксу:
версия «3.1.38.92» → редакция «3.1», «3.0.142.32» → «3.0» (работает и при «Ред = 3»,
и при «Ред = 3.0»). `Подред` используется только для устаревших сегментных адресов и для
конфигураций, где каталог делится по подредакциям; у встроенного набора адрес строится по
нику (`releases.1c.ru/project/HRM30` для ЗУП и т.п.).

**Что изменилось в 0.3.9.309.**

1. Автоопределение по `ConfigName` — база ЗУП с именем «ЗарплатаИУправлениеПерсоналом»
   теперь сопоставляется с типовой ЗУП без ручной привязки.
2. Редакция в окне F9 выбирается по версии базы («3.1.38.92» → «3.1»), а не всегда первая
   из списка; единая логика также используется окном «Связать с конфигурацией».
3. Если имя конфигурации базы не нашлось ни в одной типовой — вместо общего «База не
   связана» выводится сообщение с именем базы и подсказкой ручной привязки.

**Как проверить.**

1. Установите **0.3.9.309** (Windows или Linux).
2. В свойствах базы (вкладка «Платформа») убедитесь, что заполнены «Конфигурация»
   (например «ЗарплатаИУправлениеПерсоналом») и «№ релиза» (например «3.1.38.92»).
3. Нажмите F9 по базе (без явной привязки): окно покажет адрес
   `https://releases.1c.ru/project/HRM30` и последнюю версию из каталога, а не «База не
   связана с типовой».

Файлы для установки — на странице релиза
[v0.3.9.309](https://github.com/sivatorov/ConfigurationManagement/releases/tag/v0.3.9.309).

## РљРѕРјРјРµРЅС‚Р°СЂРёР№ 4 РѕС‚ sivatorov (2026-10-06T03:07:15Z)

Исправлено в версии **0.3.9.312** (Windows/WPF и Linux/Avalonia).

**Что сделано по вашему предложению.**

Привязка базы к типовой конфигурации теперь видна и управляется прямо в свойствах базы. На вкладке
«Платформа», под группой «Конфигурация», добавлена группа **«Привязка»**:

1. **Сводка текущей связи.** Отображается, к какой типовой привязана база: наименование типовой,
   редакция (определяется по номеру релиза из свойств базы) и адрес каталога релизов. Если база
   не привязана — вместо сводки показывается «—».
2. **Кнопка «Связать…».** Открывает существующее окно «Связать с конфигурацией» для выбора или
   смены привязки. Поля связи пишутся в базу и репозиторий сразу, как при привязке из контекстного
   меню.
3. **Кнопка «Очистить».** Активна, только если у базы есть привязка. Сбрасывает код типовой
   конфигурации, ручную ссылку и персональный сегмент с подтверждением.

Реализация симметрична для WPF и Avalonia, все тексты локализованы ru/en.

Ключевые файлы:

  новые [`BuildLinkSummary`](https://github.com/sivatorov/ConfigurationManagement/blob/main/Configuration%20Management/ViewModels/ConnectionSettingsViewModel.cs),
  [`HasLink`](https://github.com/sivatorov/ConfigurationManagement/blob/main/Configuration%20Management/ViewModels/ConnectionSettingsViewModel.cs),

**Как проверить.**

1. Установите **0.3.9.312** (Windows или Linux) и откройте свойства базы → вкладка «Платформа».
2. Если база привязана к типовой — в группе «Привязка» видна сводка (наименование типовой,
   редакция, адрес каталога) и активна кнопка «Очистить».
3. «Связать…» открывает окно «Связать с конфигурацией»: можно выбрать другую типовую — после
   сохранения новая привязка сразу отражается в сводке.
4. «Очистить» сбрасывает привязку (с подтверждением): сводка заменяется на «—», кнопка
   «Очистить» становится неактивной.
5. Проверьте обе платформы — WPF (Windows) и Avalonia (Linux) реализованы симметрично.

Исправлено в версии **0.3.9.248** (Windows/WPF и Linux/Avalonia).

**Что было сломано.** В релизах 0.3.9.233+ попытка проверить обновления платформы
(F9 / окно «Обновление платформы 1С», Ctrl+F9) заканчивалась неприятным сценарием:

1. **«Мелькание» панели статуса** — внизу окна на долю секунды появлялась и тут же
   исчезала панель прогресса/журнала, даже если проверка мгновенно завершалась сбоем.
2. **Ошибка без понятного объяснения** — сообщение об ошибке либо не показывалось вовсе,
   либо появлялась пустая строка, когда провайдер возвращал статус ошибки без ключа
   локализации.
3. **Прогресс «прыгал» в 1** — при любом исходе операции (в том числе при сбое) прогресс
   принудительно выставлялся в 1, создавая ложное впечатление «всё скачалось», хотя
   ничего не скачалось.
4. **Неперехваченные исключения провайдера** — исключения из цепочки `OneCUpdatesService`
   (сетевые сбои, редиректы, изменившаяся структура страницы каталога) могли всплывать
   до уровня ViewModel и ронять операцию без диагностики.

**Причины.**

- Панель статуса показывалась WPF-стилем через `DataTrigger` на `IsBusy`; при быстром
  сбое `IsBusy` успевал пройти `false → true → false` в пределах одного отрисовываемого
  кадра — панель «мигала». На Avalonia видимость панели переключалась напрямую из
  обработчика `PropertyChanged` — то же мгновенное появление/скрытие.
- В `finally` метода проверки безусловно выполнялось `Progress = 1` — значение прогресса
  не различало «успех» и «ошибку».
- В ветке ошибки использовался ключ локализации из результата провайдера без проверки на
  пустоту; при `ErrorKey = ""` пользователю показывалась пустая строка. Сама операция
  бросала исключение наружу (перехват в ViewModel отсутствовал).

**Как исправлено.**

- **Перехват ошибок провайдера.** `CheckUpdatesAsync` теперь оборачивает обращение к
  сервису в `try/catch`: любое исключение (сеть, вход на `login.1c.ru`, изменившаяся
  структура страницы каталога) превращается в понятное сообщение — в журнал окна,
  системное уведомление об ошибке и запись `IAppLogger.Error` с типом исключения (без
  паролей/токенов). Операция завершается штатно, приложение не падает
  ([`PlatformUpdateViewModel.cs`](Configuration%20Management/ViewModels/PlatformUpdateViewModel.cs)).
- **Fallback пустого ключа ошибки.** Если провайдер вернул статус ошибки без ключа
  локализации — подставляется общий ключ сетевой ошибки
  `PlatformUpdate.Error.NetworkError`, пустая строка пользователю не показывается.
- **Анти-мигание.** Панель статуса показывается только при старте операции и скрывается
  с задержкой **500 мс** после завершения (DispatcherTimer, обе платформы): при
  мгновенном сбое панель успевает показать текст ошибки и не «мигает»
  ([`PlatformUpdateWindow.xaml`](Configuration%20Management/Views/PlatformUpdateWindow.xaml),
  [`PlatformUpdateWindow.xaml.cs`](Configuration%20Management/Views/PlatformUpdateWindow.xaml.cs),
  [`PlatformUpdateWindow.Avalonia.cs`](Configuration%20Management/Views/PlatformUpdateWindow.Avalonia.cs)).
- **Прогресс при ошибке.** `Progress` больше не «прыгает» в 1 в `finally`: при ошибке он
  остаётся 0, видимой «загрузки» нет.

**Как проверить.**

1. Установите версию **0.3.9.248** (Windows или Linux).
2. Откройте «Обновление платформы 1С» и нажмите «Проверить обновления» (F9 / Ctrl+F9)
   при недоступном портале или без входа на сайт 1С — вместо мелькания и пустой ошибки
   внизу окна появится понятное сообщение об ошибке (сетевая ошибка / требуется вход /
   каталог не найден), а также системное уведомление об ошибке; приложение продолжает
   работать.
3. Повторите проверку при рабочем подключении — каталог версий загружается как раньше.
4. Windows и Linux ведут себя одинаково (панель статуса не «мигает» в обоих случаях).

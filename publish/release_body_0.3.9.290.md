# Управление конфигурациями 1С — v0.3.9.290

Серия из **четырнадцати исправлений** (цикл 0.3.9.277–0.3.9.290) по обращениям и задачам
проекта, закрывающая issue #340, #308, #330, #339, #324, #305, #321, #338, #333, #323,
#334, #335, #341, #309. Каждое улучшение реализовано на обеих платформах (Windows/WPF
и Linux/Avalonia), где проблема воспроизводится, с юнит-тестами; полный набор
`dotnet test` зелёный (1606), кросс-сборка Linux (`dotnet build -p:BuildLinux=true`)
без ошибок.

## Изменения

### 0.3.9.277 — [#340](https://github.com/sivatorov/ConfigurationManagement/issues/340)

Клик по строке при открытом контекстном меню больше не «проглатывается» (Windows/WPF):
после мультивыделения WPF держит захват мыши в попапе меню, и клик «для снятия выделения»
пропадал. Теперь при закрытии контекстного меню кликом по строке выбор применяется повторно
(`TryApplyTreeClickAfterMenuClosed`): мультивыделение снимается и выбирается строка под
курсором.

### 0.3.9.278 — [#308](https://github.com/sivatorov/ConfigurationManagement/issues/308)

Окно выбора скрипта: клавиатурный фокус реально попадает в список — стрелки и Enter
работают сразу после открытия, без предварительного клика мышью. Фокус переносится
повторно после полной отрисовки/активации окна (WPF — `Dispatcher.BeginInvoke(ApplicationIdle)`,
Avalonia — `Dispatcher.UIThread.Post(Background)`, на контейнер выбранной строки).

### 0.3.9.279 — [#330](https://github.com/sivatorov/ConfigurationManagement/issues/330)

Окно «Скачивание версии платформы 1С» больше не падает с ошибкой привязки TwoWay к
доступному только для чтения свойству `LogText` (Windows/WPF): в
[`PlatformDownloadWindow.xaml`](Configuration%20Management/Views/PlatformDownloadWindow.xaml)
добавлен явный режим `Mode=OneWay`; остальные окна с журналами проверены — затронуты
не были.

### 0.3.9.280 — [#339](https://github.com/sivatorov/ConfigurationManagement/issues/339)

Отбор «Только запущенные»: состав списка обновляется при изменении статусов баз —
дозапустившаяся база появляется, закрытая/вылетевшая исчезает сразу после опроса
процессов (WPF — `RebuildGroupTree`, Avalonia — `ApplyFilter`), без ожидания переключения
режима.

### 0.3.9.281 — [#324](https://github.com/sivatorov/ConfigurationManagement/issues/324)

Монитор «Серверы 1С»: вывод rac распознаётся при выравнивании пробелами и в не-UTF-8
кодировке. [`RacOutputParser.ParseTable`](Configuration%20Management/Services/RacOutputParser.cs)
получил позиционный разбор по границам колонок из строки заголовка (внутренние пробелы
имени кластера не теряются); [`RacClient`](Configuration%20Management/Services/RacClient.cs)
читает stdout/stderr сырыми байтами с автодекодированием UTF-8 / cp866 (OEM Windows) /
cp1251.

### 0.3.9.282 — [#305](https://github.com/sivatorov/ConfigurationManagement/issues/305)

Создание серверной базы: новая база наследует режим «Разрядности по умолчанию» из настроек
(а не жёстко создаётся 32-битной приоритетной); выбранная строка «server:port» гарантированно
попадает в поле (страховка `DropDownClosed`); запоминание сервера СУБД после успешного
создания проверено; в справку окна добавлено пояснение, на чём основывается выбор.

### 0.3.9.283 — [#321](https://github.com/sivatorov/ConfigurationManagement/issues/321), часть 1

Типовые конфигурации: колонка «Сегмент адреса (ник)» заменена на «Имя конфигурации»
(как в самой конфигурации 1С, например «БухгалтерияПредприятия») — значение не участвует
в построении адреса обновлений. Поле `ConfigName` добавлено в модель `OneCConfigType`,
заполнено для всех 7 типовых конфигураций, учтено в поиске; старые JSON-файлы читаются
без ошибок.

### 0.3.9.284 — [#321](https://github.com/sivatorov/ConfigurationManagement/issues/321), часть 2

Введённые строки релизов больше не теряются при сохранении: поля редакции самокоммитятся
в выбранную редакцию при каждом вводе (`TextChanged` → `CommitEditionFields`), при добавлении
строки поля очищаются; список редакций целиком переносится в модель при ОК.

### 0.3.9.285 — [#338](https://github.com/sivatorov/ConfigurationManagement/issues/338)

Окно свойств базы: в списке «Конфигурация» появляются значения «Имя конфигурации» из
справочника типовых конфигураций, даже если такой базы в списке ещё нет. Правило
объединения вынесено в общий helper `ConnectionSettingsViewModel.MergeAvailableConfigurations`
(фильтр пустых, Trim, дедупликация без учёта регистра, сортировка) — используется обеими
платформами.

### 0.3.9.286 — [#333](https://github.com/sivatorov/ConfigurationManagement/issues/333)

Учётные данные ИТС: «Задать основным» перенесена на нижнюю панель рядом с «Добавить»
(в строках остаётся индикатор «Основная»); в редакторе добавлен просмотр пароля «глазом»
(WPF — переключение PasswordBox ↔ текст, Avalonia — смена маски); проверено, что во всех
списках выбора учётных записей отображается имя, а не ключ.

### 0.3.9.287 — [#323](https://github.com/sivatorov/ConfigurationManagement/issues/323) и [#334](https://github.com/sivatorov/ConfigurationManagement/issues/334)

Портал 1С: HTTP 302 без Location от releases.1c.ru теперь распознаётся как «требуется
авторизация» (`Updates.AuthRequired`), а не технический «HTTP 302» — выполняется программный
вход на portal.1c.ru (один раз за сессию службы) и повтор исходного запроса с cookie;
каждый редирект логируется с номером шага и Location. Обновление платформы (#334): выбранная
учётная запись ИТС доходит до `GetCredentials()`, при отсутствии настроенных учётных данных
показывается понятное сообщение «Требуется вход на сайт 1С», а не голый NetworkError.

### 0.3.9.288 — [#335](https://github.com/sivatorov/ConfigurationManagement/issues/335)

Диагностика подключения: кнопка «Проверить порты 1С» открывает модальный диалог с таблицей
сервисов (агент, кластер, хранилище конфигурации, RAS) и редактируемыми портами; при открытии
порты «угадываются» по образцу нестандартного порта кластера (`ServerPortsGuesser`,
2541 → 2540/2541/2542/2545); RAS-порт сохраняется в настройках сервера; новые окна
`PortsEditWindow` (WPF и Avalonia) с локализацией `Ports.*`.

### 0.3.9.289 — [#341](https://github.com/sivatorov/ConfigurationManagement/issues/341)

Свёртка/развёртка ветки дерева групп: **Ctrl+клик** по группе — развернуть/свернуть группу
со всеми подгруппами; горячие клавиши **Ctrl+Alt++ / Ctrl+Alt+-** — развернуть/свернуть ветку
под курсором. Логика вынесена в ViewModel обеих платформ (`ExpandBranchOf`/`CollapseBranchOf`),
покрыта тестами `GroupNodeViewModelTests`.

### 0.3.9.290 — [#309](https://github.com/sivatorov/ConfigurationManagement/issues/309)

Горизонтальный скролл списка баз (Windows/WPF), девятая попытка: расширенная диагностика
в логе `CM_COLUMNS` (фактические ширины колонок заголовка и первой строки, ширина окна,
влияние вертикального скроллбара — эксперименты A/B) плюс два безопасных фикса-минимума:
минимум контента прокрутки учитывает фактическую сумму колонок заголовка (включая растянутую
звёздную «Название»), а после применения настроек колонок список принудительно прокручивается
до конца горизонтальной полосы (`EnsureHorizontalReach`). Просьба к пользователям: прислать
новый лог `CM_COLUMNS`, чтобы подтвердить гипотезу обрезания последних колонок.

Исправлено в версии **0.3.9.288** (Windows/WPF и Linux/Avalonia).

**Что сделано по итоговым требованиям:**

1. **Одно поле «Сервер».** В окне «Диагностика подключения» один редактируемый список серверов (как при правке базы) с подстановкой сохранённого порта кластера; отдельного поля «СерверЫ» больше нет.

2. **Кнопка «Проверить порты 1С» открывает отдельный диалог** [`PortsEditWindow`](Configuration%20Management/Views/PortsEditWindow.xaml)/`.Avalonia.cs` — таблица из двух колонок: «Описание сервиса» (только чтение) и «Порт» (правится только порт): агент (ragent), кластер, хранилище конфигурации, RAS. После подтверждения порты сохраняются для этого сервера ([`ServerPortsStore`](Configuration%20Management/Services/ServerPortsStore.cs)) и сразу сканируются.

3. **Догадка портов при открытии диалога** (новый чистый helper [`ServerPortsGuesser`](Configuration%20Management/Services/ServerPortsGuesser.cs)): если в главном окне указан порт, отличающийся «началом» от стандартного (например **2541** вместо **1541**), остальные порты вычисляются по образцу: **2540 (агент) / 2541 (кластер) / 2542 (хранилище) / 2545 (RAS)**. Сохранённые для сервера порты имеют приоритет над догадкой; стандартные и недопустимые значения дают стандартную карту без сдвига.

4. **Сохранение порта RAS**: [`ServerPortsSettings`](Configuration%20Management/Services/ServerPortsStore.cs) дополнен полем `Ras` (со значением по умолчанию — старые `server_ports.json` читаются без ошибок).

**Тесты.** Новый [`ServerPortsGuesserTests`](ConfigurationManagement.Tests/ServerPortsGuesserTests.cs): пример из issue (2541 → 2540/2541/2542/2545), стандартные порты, недопустимые значения, верхняя граница диапазона. [`NetworkDiagnosticsViewModelTests`](ConfigurationManagement.Tests/NetworkDiagnosticsViewModelTests.cs): `BuildPortsForEdit_*` (догадка + приоритет сохранённых) и `ApplyEditedPortsAndCheckAsync_ScansEditedPorts_AndSaves` (сканирование и запоминание отредактированных портов). Полный набор `dotnet test` зелёный (1604), кросс-сборка Linux (`dotnet build -p:BuildLinux=true`) без ошибок.

**Как проверить:**

1. Установите **0.3.9.288** ([релиз v0.3.9.288](https://github.com/sivatorov/ConfigurationManagement/releases/tag/v0.3.9.288)).
2. Откройте «Диагностика подключения» (правый клик по базе → Диагностика), в поле «Сервер» выберите сервер; в поле порта введите, например, 2541.
3. Нажмите «Проверить порты 1С»: откроется диалог со строками 2540/2541/2542/2545 (агент/кластер/хранилище/RAS) — поправьте при необходимости, «Проверить».
4. Порты сохранятся для сервера: при повторном открытии диалога будут подставлены сохранённые.

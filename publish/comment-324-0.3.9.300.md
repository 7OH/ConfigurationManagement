Исправлено в версии **0.3.9.300** (Windows/WPF и Linux/Avalonia).

**Что было.**

Команда `rac cluster list` на новых версиях rac выполняется успешно (`exit=0`), но монитор «Серверы 1С» показывал «Подключение установлено, но кластеры не найдены». Дело в формате вывода: rac стал выдавать не таблицу, а блоки «ключ : значение» с выравниванием пробелами и двоеточием:

```
cluster                                   : cbc95ef0-99c9-4b1a-909f-cff4c8de61d9
host                                      : ALF
port                                      : 27541
name                                      : "Локальный кластер"
```

Парсер [`RacOutputParser.ToClusters`](Configuration%20Management/Services/RacOutputParser.cs) был рассчитан только на табличный формат (заголовок + строки колонок) — вывод «ключ : значение» не извлекался, и список кластеров оставался пустым, хотя подключение проходило.

**Что сделано.**

1. [`Services/RacOutputParser.cs`](Configuration%20Management/Services/RacOutputParser.cs): `ToClusters` при пустом табличном разборе переключается на разбор блоков «ключ : значение» — вывод делится на блоки по повторяющемуся ключу `cluster` (значение — GUID), внутри блока извлекаются `name`, `port` и (при наличии) `host`; значения снимаются с кавычек (`"Локальный кластер"` → `Локальный кластер`).
2. Общий helper `TryParseKeyValueBlocks(output, spec)` — единый путь разбора, устойчивый к обеим версиям rac (табличный вывод и key-value блоки).
3. **Тесты** ([`RacOutputParserTests.cs`](ConfigurationManagement.Tests/RacOutputParserTests.cs)): реальный вывод из issue (`ToClusters_ParsesKeyValueBlocks`), несколько блоков подряд, имя в кавычках, регрессия — табличный формат по-прежнему разбирается.

**Как проверить:** обновитесь до **0.3.9.300**, откройте «Серверы 1С» и подключитесь к кластеру (`host:port`) — список кластеров/процессов/сеансов должен заполниться (учитывая прежние исправления декодирования вывода и позиционного разбора таблиц).
